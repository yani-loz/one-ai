## 1. Core principles

1. **Answers before the system.** Gold answers are written by hand BEFORE the code runs, on the exact input the system will see. Grading is a mechanical diff against the key — never "inspect the output and judge".
2. **Frozen and tamper-evident.** Once audited, every file is hashed into a manifest. Runners verify the manifest first and refuse on mismatch. Nothing — including the build agent — can quietly bend the answer key.
3. **Three-way split: optimization / test / validation** *(v1.1, 2026-08-29 — founder requirement; supersedes the v1 two-way calibration/sealed split)*. Every set an optimization loop will run against (Phase 0: QS, NF, LANG, RET — deterministic heuristics overfit visible examples too, v2 checklist 2026-09-06; later: SCOUT, ANT, PAIR) is split in three at leakage-group level — **and any other labeled set is either split the same way or lives, unsplit, in the hidden root as a validation-only holdout from the freeze — never scored by the loop** (verification 2026-09-06, P0-02: "targeted by a loop" means the set's gate participates in a /goal condition an agent iterates on — for Phase 0's `17/17` that is every gate from the first run, so "split when targeted" cannot be deferred; a visible single labeled set inside a /goal loop is the test measuring itself, and a hidden single set scored at checkpoints would both tune and accept, which the floors bullet below forbids. Phase 0: FID, THR, IDENT, ATTR are validation-only holdouts — touched once by the founder at final acceptance, their loop-facing gate signal coming from public fixtures + a corpus invariant DEFINED in the criterion (THR, IDENT, ATTR; FID has none — fixtures only). Each such gate carries two criteria ids — `<gate>.provisional` (fixtures + defined invariants, its own declared minimum denominator, frozen at stage B) and `<gate>.validation` (`pending` until the founder run) — because the criterion sheets' denominators were authored for the labeled set and are empty in the loop; the gate counts toward 17/17 on the provisional basis and the verdict line carries `provisional=<p>:<gates>`. Such a holdout MAY serve as a pass/fail gate at that one founder run — and only there — when it independently clears its criteria's declared minimum denominators; below that floor the whole gate is declared directional BEFORE the freeze, stays provisional forever (counted in `<p>` on every run, the founder run included) and is named in the verdict line's separate `directional=` field — never as an annotation inside `provisional=`. If a validation-only holdout FAILS at final acceptance, the holdout is consumed: it is never re-run as hidden evidence and the loop may not resume against it in place (re-running it hidden would convert it into a test split) — it MAY be moved into the OPTIMIZATION split as visible regression evidence, never again as an acceptance test for the fixes its failure caused (v2.4) — a fresh labeled holdout for that gate is drawn — excluding every leakage group present in the public fixture battery and in the consumed holdout — and audited under the (possibly amended) PROTOCOL, a superseding release lock is cut (§11; a byte-identical hidden test split keeps its spent budget, §8.7) and the failure becomes a pinned case, synthesized after the failure mode, never a verbatim holdout record. An aborted founder run (ERROR before any verdict line) is not a failure: it is recorded as an aborted attempt and may be reset once by the founder (§8 item 9). A weaker claim than three-way, stated as such in the report; the founder may upgrade them):
   - **optimization** — fully AI-visible; tuned against freely (thresholds, anchors, prompts, model choice);
   - **test** — cases **mechanically hidden** from the optimizing agent (§10a); scored only through the single runner command, aggregates only, at accept-checkpoints — never per mutation;
   - **validation** — hidden the same way; touched **exactly once**, at final acceptance, run personally by the founder. A test↔validation disagreement is an overfitting red flag: investigated, never re-rolled.

   Homework / mock exam / final exam. Default ratio 50/30/20, allocated **floors-first**: the split assignment must satisfy each scored cell's minimum counts (§7.5) in the hidden splits first — the ratio is only the residual default — and when floors cannot be met, the set GROWS (or the cell goes out of scope via the §5.0 census); re-slicing never repairs missing evidence. **A set is split three ways only when EACH scored split independently clears its criteria's minimum denominators** (v3, F12) — a criterion evaluated on a 30-query test sliver passes coin-flip retrievers too often to gate anything; otherwise the set grows, or it uses a single hidden holdout and the affected criterion is stated as a directional check with its interval, never a pass/fail gate. This is a sizing fallback, not a statistical prohibition on single holdouts: under the explicit Phase-0 validation-only policy, an unsplit holdout may support a final pass/fail gate when it independently satisfies every required minimum and provides no development feedback; a holdout below a required minimum supports only a directional report and cannot contribute a PASS on its own evidence (the gate stays provisional on its declared loop-facing basis — F+C, or F only for FID — v2.4, GPT-6). Deterministic-invariant sets (CH) and PII-free fixtures gain nothing from hiding and stay unsplit. *(Fixes Codex blocker #2 — the same data must not tune AND accept — and closes the stronger loophole: blindness by policy alone.)*
4. **One standard, many sets.** Each phase has its own sets (different label types), but all share the same record core, release mechanics, runner contract, and versioning. Build the factory once.
5. **Honest claims.** Acceptance certifies **finite-set conformance** ("0 failures on step1-gold-v1") plus regression discipline — NOT population claims ("<1% in the wild"). Population-grade certification is parked (§13). *(Fixes Codex blocker #3 by reframing, plus targeted size increases.)*

## 2. The record standard

### 2.1 Shared core (every record in every set)

```
gold_id · set_id · set_version · split (optimization|test|validation)
input:  { exact system-visible snapshot (verbatim), source ref, snapshot_sha256,
          renderer/parser/quote-stripper/chunker versions }
label:  { per-set typed schema — see 2.2 }
strata: { language: bg|en|mixed · format tags · length (numeric + bucket) ·
          attachment types/count · adversarial tags }
leakage_groups: { thread id · near-duplicate/template cluster · attachment content hash }
provenance: { labeled_by (model+config hash for pre-labels) · review_status:
              unreviewed | reviewed_agree | corrected | adjudicated | excluded ·
              protocol_version · origin (initial | bug-YYYY-MM-DD | posthoc-qrel) }
note
```

- **Offsets are UTF-8 byte offsets into the exact snapshot** — never character indexes, never any model's token offsets (tokenizers differ per candidate model).
- `review_status` replaces a boolean "audited" — corrections and exclusions must be visible.
- Where truth is genuinely non-unique, the label lists acceptable alternatives.

### 2.2 Per-set label schemas (typed, versioned — one universal label union is forbidden)

| Set | Label shape (essentials) |
|---|---|
| QS (quote stripping) | **spans** (UTF-8 byte offsets into the frozen snapshot) for: new content · redundant quote · signature · forwarded content — the boolean `has-signature` is insufficient (v2 checklist, 2026-09-06); observed-structure tag (reply/forward/inline/top-post · quote delimiters · signature/logo · plain/HTML) — client attribution `verified` / `unknown`, never inferred from a text template. Retention/echo/signature mass are measured over the full chunker-bound embedding input (body + derived text fields + metadata header) — whose FIELD SET is the one CH's cap is measured on (Phase-0 ruling (f)) — plus every other retrieval/serving surface enumerated by name in criteria at stage B (lexical/search representations, fields returned with a retrieval unit or on thread expansion, attachment/carrier metadata); never over a single "cleaned body" field, otherwise stripped-but-relocated quote/signature text scores zero mass while still reaching a reader (v2.3) |
| CH (chunking) | none — invariants checked mechanically (full corpus + ≥30 boundary fixtures; tokenizer pinned in criteria) |
| NF (attachment noise) | document \| noise(type) · duplicate-group id (canonical content + carrier edges) — OCR-required and unsupported-format files are labeled **document**, never noise |
| LANG | bg \| en \| mixed \| und — under the frozen operational definition (mixed = each language ≥ 20% of language-bearing word tokens, ≥ 5 tokens each; short-text and transliteration rules in PROTOCOL), assessed on quote/signature-stripped prose |
| RET (retrieval) | query · language · **relevant SOURCE SPANS + acceptable evidence alternatives** (authored before any chunker exists; resolved mechanically to candidate chunks by provenance — chunk ids are resolved artifacts, never the answer key) · direction (BG→EN \| EN→BG \| same) |
| **COV** (v2) | none — frozen physical-input roster + scope policy; every input's disposition: delivered \| explicitly excluded(reason) \| not-ready |
| **FID** (v2) | per source-backed case: required content units (paragraphs/list items · link label–destination · page/column order · table tuples `(sheet,row,column,value,header)`) from the ORIGINAL file, never from current extracted text; encoding fixtures |
| **THR** (v2) | required resolvable links (must-join pairs) · forbidden pairs (must-not-join) · collision/missing-parent/reordered-ingest fixtures |
| **TIME** (v2) | per message: declared source value · parsed instant (or `unknown-zone` state) · sent/received/ingested provenance |
| **IDENT** (v2) | participant observations (address, role) · verified alias pairs (with provenance) · must-remain-distinct pairs |
| **RED** (v2) | synthetic secret-shaped canaries by class (positives, incl. beyond the scan cap and across surfaces) · protected non-secret control spans (negatives) |
| **ATTR** (v2) | per forwarded segment: forwarding sender · claimed original author (nullable only as the frozen state policy allows) · source-span provenance · state `recoverable` / `ambiguous` / `unresolvable` (never NULL; v2.4) |
| **SNAP** (v2) | none — canonical text hash per artifact across two clean replays; normalization/mapping fixtures (Cyrillic, emoji, combining, CRLF, NBSP, repeated text, typographic punctuation) |
| **EMB** (v2) | none — per required chunk: vector present · model/tokenizer/preprocessing version · reproducibility check; execution-contract fixtures (zero generative calls, zero unapproved egress) |
| SCOUT | multi-label: which kinds are present |
| ANT | **one record per INPUT with 0..N findings** (never one record per finding — empty inputs and false positives must be scorable); field-level gold per finding, with evidence spans |
| PAIR | relation: same \| amendment \| conflict \| unrelated |
| GATE (poison) | must-block: entity-leak \| PII \| k-anonymity \| single-source |
| SERVING | required rows · forbidden rows · required citations · ordering semantics · acting person + rights fixture |
| LIFECYCLE | scenario fixtures with expected end-states |

**RET post-hoc rule:** when a model arm retrieves an unlabeled chunk, the founder judges it (relevant/not) and the qrels grow — labeled `origin: posthoc-qrel`. This fixes the "unknown relevant unfairly penalized" problem without full TREC pooling.

## 3. Release structure (storage & tamper evidence)

```
Benchmarks/_mem01_gold/                      ← OUTSIDE the repo (contains PII)
└── releases/step1-gold-v1/
    ├── dataset.manifest.json                ← sha256 of every data file + record-ID roster + counts
    ├── criteria.step1.v1.yaml               ← the formula sheet (see §6) — hashed into the manifest
    ├── PROTOCOL.v1.md                       ← labeling rulebook (non-PII; a copy lives in the repo)
    ├── schemas/                             ← core + per-set JSON schemas (hashed)
    ├── sample_seed.json                     ← sampling frame, random seed, strata cells, split assignment
    └── data/optimization/ *.jsonl           ← the AI-visible split ONLY

Benchmarks/_mem01_hidden/                    ← the hidden root (v1.1): OUTSIDE the agent workspace,
└── releases/step1-gold-v1/                    covered by permission deny rules (§10a)
    ├── test/ *.jsonl                        ← checkpoint scoring only, via the runner
    ├── validation/ *.jsonl                  ← one-shot final acceptance, founder-run
    └── reports/                             ← per-case diffs land HERE, never on stdout
```

- The repo holds only: the manifest hash ("release lock"), PROTOCOL.md, schemas, and the criteria file. Data never enters git.
- **One manifest covers all three splits** (it lives in the visible release; hashes and counts reveal no case content). The runner verifies visible and hidden files against the same manifest.
- Sampling is scripted: recorded seed, declared strata (language × format × length × attachments), leakage groups computed BEFORE the split, split assigned at group level (no thread/template straddles two splits).
- PII hygiene v0: local disk, outside repo; encryption/ACL hardening → §13.

## 5. Labeling protocol

0. **Cell feasibility census (v3, F12 — mandatory, BEFORE sampling):** for every planned scored cell, run a high-recall lexical census over the full corpus, deduplicate to leakage groups, and record `candidate_groups`. A cell failing **§7.5's yield-adjusted feasibility inequality (the single source for the threshold — this step defines the procedure, never the number)** is declared **OUT OF SCOPE at design time** — removed from the scored grid before sampling and named in the manifest (`cells_out_of_scope`); the report banner scopes every ranking claim accordingly. A corpus cannot be grown by wishing — this is where "the set GROWS" meets reality. (Census 2026-08-30 on the live corpus: operating-rule × en = 43 candidate groups → out of scope for per-language claims.)
1. Scripted sample draw (seed + strata recorded) → AI pre-labels everything (pre-label model + config hash recorded per record).
2. Founder audits per the shares in §4. **Disagreements amend PROTOCOL.md first**, then the rest is relabeled under the corrected rule (a disagreement fixes the law, not just the record).
3. Freeze: manifest + criteria hashed; release named (`step1-gold-v1`).
4. After any protocol change: a **fresh validation draw** is audited (never reuse the old audit as proof for new rules).
4a. **Empties construction gate (at freeze — v3 scope fix, F15):** the surface-separability requirement applies to the **curated adversarial-empties slice ONLY**: a trivial classifier (length, format tags, language, attachment count) must not separate those ~100 hard empties from gold-non-empty inputs above AUC 0.60, tested per kind, waivers recorded. **The main EmptyHonesty denominator — naturally-occurring kind-empty inputs — is deliberately NOT surface-matched**: real empty mail IS separable by length (measured 2026-08-30: a single length threshold classifies at 79.5% against a 54.9% base rate), and forcing inseparability there would replace the production-shaped denominator with a second adversarial one. The remedy for a failed gate redraws the adversarial slice only — **never the ANT input set**, whose composition the Recall and Precision denominators depend on.
5. Honest naming: AI-labeled + partial audit = *validated silver*; the fully-audited sets (RET, ANT, PAIR, GATE, SERVING) are gold in the strict sense. The distinction is recorded per set.
6. **Builder ≠ optimizer.** The session that pre-labels and freezes a set necessarily sees every case (labels must be built and audited). Blindness begins at freeze: hidden splits move to the hidden root, deny rules activate (§10a), and every later optimizing session is a fresh context that has never seen them. The freeze is the blindness boundary; the founder audits across all three splits.

## 6. Criteria as formulas (the PR-formula strategy, adopted)

Every criterion in `criteria.*.yaml` is written the way the PR Score v2 document writes scoring — **scales, formula in words, worked example, and edge policies**:

- **Defined scales** for every component; values outside scales are schema errors.
- **Formula in words** with explicit numerator and denominator (e.g., *QS-loss = emails with ≥1 lost required new-content scalar ÷ emails with new content in the scored split; PASS ⇔ QS-loss = 0*).
- **Edge policies declared** per criterion: missing prediction, duplicate, abstention, parse error, zero denominator (an error NEVER shrinks a denominator).
- **A worked example** with concrete numbers.
- **Minimum denominators** per slice (a criterion silently evaluated on 3 records is void).

**The one hard rule: acceptance is GATES ONLY.** PASS/FAIL is a conjunction of criteria — never a weighted composite (a blended 94/100 can hide lost content). Precedent from the PR formula itself: Тон = 0 → *not scored, logged separately* — a gate, not a weight.

### 7.1 The formula

> **ArmScore_cell = 100 × ( 0.70·F_β(Recall, Precision) + 0.20·FieldQuality + 0.10·EmptyHonesty )**, per kind × language cell, where **F_β = (1 + β²)·P·R ÷ (β²·P + R)** with **β = 0.7** (β² ≈ 0.49: precision weighs roughly twice recall), defined as 0 when P + R = 0. β = 1 recovers plain F1.

**β = 0.7 is a frozen RANKING PREFERENCE, declared with its reason and its limits (v5.3 — supersedes v5.2's "harm ratio" framing on GPT-6 Astra's derivation):** F_β's denominator weights FN and FP in the ratio 1 : β² (2.04 at β = 0.7), but the *marginal* assertion threshold for a candidate finding correct with probability p is p > F_β/(1+β²) — for the honest operating point (P 0.80, R 0.71) that is p* ≈ 0.52, an effective wrong-to-missed ratio of ≈ 1.06, and it drifts with the arm's P and R. So β is not an elicited constant harm ratio; it is a frozen preference for precision over recall, and the field utility {+1, 0, −1} and the lifecycle gates are separate declared preferences, not consequences of it. **What the preference buys (repaired simulator, lexical kill + exact per-run F_β, 2026-09-06):** the selective-spam arm (junk only on non-empty inputs — R 0.89, P 0.58) clears the floors and under β = 1 out-scores honest (76.9 vs 74.6); under β = 0.7 honest leads (75.6 vs 73.7); under β = 0.5 low-recall precision is over-rewarded. **What it costs, stated plainly:** a precise low-recall arm (R 0.57, P 0.88) ranks ABOVE honest at β = 0.7 (80.6 vs 75.6) — that is the preference working as declared, and only the Recall-floor coward (R < 0.40) is categorically excluded. The "missed state change leaves an actively-false card" concern is carried by the lifecycle gates (§7.4), not by β. *Parked founder decision:* a constant-cost utility U(c) = 1 − (FN + c·FP + λ·field errors) ÷ fixed gold denominators gives the same threshold c/(1+c) at finding and field level with ONE frozen harm ratio — adopt it only if a single elicited constant is wanted; it changes how the PR-style components read. Changing β after any score is visible invalidates the ranking.

**Why a coupled F replaced the additive 0.35·R + 0.35·P** (v2, both reviewers independently): the additive form had no interior optimum — a **selective-spam arm** (45% of its output wrong) scored 79.5 and a **coward arm** (55% of facts missed) scored 77.0, both above an honest balanced arm at 76.5. In a memory product those are the two worst behaviours: durable wrong knowledge, or a memory that is mostly empty. Coupling P and R fixed the coward for good; **β = 1 did not fully fix the spam** — the stress test found the spam arm still wins at P ≈ 0.62–0.64 (see the β paragraph above) — which is why v5.2 weights precision. A genuinely strong arm (R .85 / P .88) scores 87 under every form considered — the change costs nothing where it shouldn't.

**The floors are a backstop, not the defense (v5.2).** Under v2–v5.1 the Precision floor at 0.60 was load-bearing: it was the only thing keeping a near-tie spam arm from a winner claim, and it therefore had to sit inside the operating band of realistic small models — where the stress test measured **20% false ineligibility at true P ≈ 0.62 and 65% at ≈ 0.59**. With β = 0.7 the ranking itself separates junk from honesty, so the floors return to what §7.4 always said they should be — "obviously unusable" lines far below the operating band (P ≥ 0.50, R ≥ 0.40; the false-ineligibility rate at true P 0.60–0.66 drops to ≤ 5%). **How a floor bites is defined ONCE, in §7.4's state machine — this section never restates it** (v4: two v3 restatements of the same rule disagreed, and that disagreement was itself an exploitable defect).

**Worked example (per §6's own rule).** An arm posts R = 0.82, P = 0.88, FQ = 0.85, EH = 0.95, all gates green: F_0.7 = 1.49·0.88·0.82 ÷ (0.49·0.88 + 0.82) = 1.075 ÷ 1.251 = 0.859 → ArmScore = 100 × (0.70·0.859 + 0.20·0.85 + 0.10·0.95) = 60.1 + 17.0 + 9.5 = 86.65 → **87** (whole-point print, §7.7; v5.3 corrects v5.2's truncated 86). The same arm with P = 0.55 computes F_0.7 = 0.617 → 69.7 → **70**: it stays eligible (P ≥ 0.50) and simply loses by 17 points — under v5.2 the ranking, not a gate, does that work. Only below P = 0.50 does §7.4's state machine take over (point estimate below the floor ⇒ GATE_FAIL; interval wholly below ⇒ DQ).

**Component availability (v4 — the void rule, F2 + R2-F2).** Each component of a cell is AVAILABLE or VOID, **evaluated at the same N=3 aggregation the scored statistic uses** (matched pairs summed across the three runs — a single thin run cannot void a component the aggregate supports). **A void component never reweights the composite, never zeroes it, and never removes the cell arm-dependently** (reweighting-on-void made ArmScore *decrease* in recall — verified: R 0.76 → 81.5 reweighted vs R 0.80 → 73.7 scored). **Gold-caused voids are impossible after freeze (v5, R3-F4):** `kind_empty_inputs ≥ 20` per scored split-cell is a frozen-roster requirement alongside the finding floors, and any gold-caused VOID is a **freeze failure or a pre-arm out-of-scope decision** — never a runtime state. **Arm-caused unavailability of a required component ⇒ `ArmScore_cell = VOID`, the arm's overall scalar = VOID, the arm is ineligible and excluded from the TOP SET**, its computable components printed — no renormalization, no zero substitution, no silent cell removal (v4 left the composite for this case undefined; a renormalized 81.1 vs a zeroed 73.0 is the size of the hole). FieldQuality is available by construction for any floor-clearing arm because the per-cell gold floor is *derived* as ceil(20 ÷ RecallFloor) = 50 (§7.5 — a non-severable constant pair; v5.1 precision: the 20-pair minimum is enforced on the SUMMED N=3 count, so 50 makes even a single run sufficient and the summed count ≥ 60 — deliberately conservative, because 50 also serves inference under §7.5(b)). FQ at 0–19 aggregated matched pairs is VOID — INCOMPARABLE, not zero (v2's "0 at zero matches" withdrawn as non-monotone). **Per-run rule (v5.3, GPT-6 F12):** the 20-pair minimum is pooled, but every run contributing to the mean-of-three score must have a positive FQ denominator — matched counts (0, 30, 30) pass every gate yet leave run 1's FQ as 0/0 and the scalar undefined; such an arm is VOID, never 0.5, never renormalized. Pairs with zero evaluable field weight do not enter the denominator. Fixture: `(0, 30, 30)`.

### 7.2 Matching (which prediction counts as which gold finding)

- **Eligibility:** same input AND same kind AND compatible per-kind identity key where the kind defines one (e.g. `aspect_key`) AND **compatible lifecycle FAMILY** (v4, R2-F14: `commitment_cancelled` predicted against a gold `commitment_made` is a state inversion, not a match — event codes are grouped into frozen families in PROTOCOL: created/confirmed · changed/revised · cancelled/withdrawn · fulfilled/resolved; cross-family pairs carry no edge, so a state-inverting prediction is an FP + FN, never a "full true positive"). Identity keys and families frozen in PROTOCOL.
- **Span predicate — three clauses, all required (v3):** predicted primary span matches a gold span iff `overlap_bytes ≥ 0.5 × len(gold_span)` **AND** `IoU ≥ 0.20` **AND** `len(pred_span) ≤ max(2 × len(gold_span), len(gold_span) + 100 bytes)`, tested against **any** span in the gold finding's `acceptable_primary_spans`. The first clause admits correct extractions that quote extra context (v1's IoU ≥ 0.5 double-penalized a 130-byte quote of a 55-byte gold fact); the second and third bound the superset — **the IoU-ratio cap alone** (5 × a median ~84-byte Bulgarian gold sentence ≈ 420 bytes) admits spans on the scale of a whole body, since 49.7% of 1,123 sampled bodies carry ≤ 555 bytes of new content *(provisional single-sourced measurements — re-established by the versioned census instrument at freeze)* — so the absolute clause is what actually forbids wall-of-text spans. **Lengths, overlap and IoU are measured in Unicode scalar positions** (a frozen mapping; raw UTF-8 byte offsets are kept for provenance and quote resolution only — v5.3, GPT-6 Q3d: byte caps gave Latin text a +100-*character* allowance but Cyrillic only +50, worth up to 1.4 cell points per lost match and ~3.5 overall points at 10% prevalence). **SpanBreadth reports per language**, and the runner's diagnostic sweep rescores at absolute caps 160/240/360 characters alongside the IoU floors.
- **Duplicates & anti-harvest (v5, R3-F3 — identity is semantic, not span-only):** a **duplicate** is a prediction whose **normalized semantic identity** — kind + identity/lifecycle key + scored field values + **resolved speech-event occurrence** (v5.3, GPT-6 F3: two genuine occurrences with identical scored values at different evidence locations are two findings; pruning them to one made gold fed back as predictions score 65 instead of 100) — equals that of an earlier-emitted prediction on the same input; span-only pruning contradicted the atomic-output contract (one sentence legitimately carries several distinct findings). Overlap classes are **deterministic connected components** over the same-identity relation; each class is pruned to its lowest-emitted-index member before assignment; pruned members stay counted predictions (Precision + DuplicationRate). **Matching stays strictly one-prediction-to-one-gold**; `shared_evidence_group` does NOT let one prediction serve N golds — it only permits several *semantically distinct* predictions to cite the same evidence span without being called duplicates. Conformance fixtures: gold-self-match (gold fed back as predictions scores exactly 1.0 — including two distinct occurrences with identical scored values), identical-span/field-distinct (two findings on one sentence both match), objective steps 2–3, and this pruning — the runner refuses to score if any fixture fails.
- **Assignment (v3 — normative, computable; supersedes "Hungarian/max-cardinality" prose):** per (input × kind), over the bipartite graph whose left nodes are the gold findings and right nodes are **all counted predictions of that kind; gate-killed and malformed predictions carry NO edges** (they can never occupy a gold) but remain in Precision's denominator. The matching is chosen by, in order: (1) **maximum cardinality**; (2) among those, **maximum sum of per-pair IoU**, each pair's IoU being the *maximum* over the gold's `acceptable_primary_spans` (argmax span id recorded); (3) the **lexicographically smallest sequence of (gold canonical offset, `gold_finding_id`, original prediction index) triples** (v5.3, GPT-6 F2: two golds may share an offset under `shared_evidence_group`, so offset + index was not a total order; `gold_finding_id` is frozen and unique). Step 2's per-pair IoU is the maximum **over the acceptable occurrences that satisfy the predicate** (normative, v5.3). Implementation needs no matching enumeration: fix the optimal cardinality and IoU sum, then walk candidate edges in the tie order, keeping each edge iff an optimal completion remains feasible — never a floating-point epsilon tie-break. **Field values never enter the objective** (they would select the most flattering pairing and inflate FieldQuality). The runner ships a conformance fixture — gold A1=[0,100), A2=[50,150), predictions p1=[0,100), p2=[0,60) ⇒ exactly 2 matches — and refuses to run if its scorer returns 1 (a max-total-IoU solver does).
- **Duplicates:** a second prediction resolving to an already-matched gold counts against Precision AND is tallied in a separate `DuplicationRate` column — redundancy is a real defect but must never be confused with fabrication.
- **Gold requirement:** ANT gold findings carry `acceptable_primary_spans` — every span that independently evidences the fact (one fact said twice = one finding with two spans; two genuine speech events = two findings) — and `shared_evidence_group` labels where one sentence carries several findings. **PROTOCOL rule (v5.2, corrected v5.3 — GPT-6 F4):** for every evidence occurrence the labeler records a fact-bearing **`core_span`** (the minimal clause carrying the event and its principal object) AND its **`sentence_envelope`**. **The overlap and IoU clauses are tested against the core span; the envelope supplies only the reference length for the cap** (`|pred| ≤ max(2·|envelope|, |envelope| + 100)`). v5.2's envelope-as-acceptable-span let a prediction quoting the *unrelated half* of a sentence — zero overlap with the fact — match with IoU 0.5; fixture: such a prediction must NOT match. The absolute cap is a cliff by design (repaired simulator: score flat at 77.8 for quotes up to 2.0× the reference, **34 at 2.5× and 23 at 3×**) — it is the wall-of-text defense, and the envelope gives it a fair reference length.
- **Span resolution (v3 clarification, F9):** the ant contract is NOT changed — findings carry `{source, segment_id, quote}`, no offsets. The HARNESS resolves the quote designated by `primary_evidence_span_id` (that span and no other is what the predicate tests) via EVID_NORM_V1 within the declared segment only, then maps back through the reverse offset table to **snapshot-global raw UTF-8 byte offsets — all span arithmetic (overlap, IoU, length caps) runs exclusively in raw snapshot byte space**; normalization finds the match, never measures it. A quote that fails to resolve, resolves ambiguously, or resolves outside its segment yields an **unmatched prediction, never a dropped one**. *Build dependency, stated plainly: EVID_NORM_V1 and its reverse offset table do not exist in the codebase yet (verified 2026-08-30) and must land — with a BG/EN round-trip property test (curly quotes, em dashes, NBSP, collapsed whitespace) — before any arm is scored.*
- **Stability diagnostic:** the runner rescores at IoU floors 0.10 / 0.20 / 0.30 and prints all three. **Rank movement across floors = metric artefact, not model quality** — investigated before any ranking is accepted (this is also the detector for span-boundary fitting, Goodhart attack (b)).

### 7.3 Components

- **Recall** = matched gold ÷ **all gold findings of the kind in the slice — end-to-end, including gold inside inputs the scout never routed**. Otherwise a tightened scout farms Precision/FieldQuality by hiding hard inputs (both reviewers, independently). This denominator and gate G2 are a matched pair — never edit one without the other. Scout-filtered kind-empty inputs DO earn EmptyHonesty: that is genuine end-to-end behaviour.
- **Precision** = matched predictions ÷ **all parsed findings the model emitted, counted BEFORE the verbatim/lexical-grounding gates AND before any field-level schema check** (v2's anti-laundering rule, tightened v3: finding-level validity NEVER removes a finding from the denominator — a finding that parses as a JSON object is a counted prediction; one with a field violation is counted, unmatched, edge-less, and tallied in `MalformedFindingRate`; excluding it would let one empty string launder a low-confidence finding out of Precision). An input whose response fails JSON parsing after the cause-aware retry contributes zero predictions while **its gold stays in the Recall denominator in full** (`ParseFailureRate` reported) — an error never shrinks a denominator (§8.4, applied at finding level). Zero predictions ⇒ Precision = 0, never undefined.
- **FieldQuality (v4 — FIELD_MATCH_V1, frozen in the criteria file).** Equality per field type, never inferred: closed enums = exact code equality (no case-fold — declared, not assumed); raw strings = EVID_NORM_V1-normalized equality against the gold value **or any entry in that field's `acceptable_values`** (gold lists boundary variants); numerics = **NUM_NORM_V1** equality — a versioned parser with frozen decimal/thousands rules and a unit-alias table (лв/BGN/lv · % · дни/days …), its version part of the run identity, unparsable values tallied in `UnparsableNumericRate` (v4, R2-F15: without this, "value+unit equality" is not reproducible on bilingual data).
  **Scope and scoring (v4, R2-F14 — abstention must not pay):** FQ is computed over **gold PRESENT and AMBIGUOUS fields only** — an honest null on a NOT_STATED/NOT_APPLICABLE slot enters nothing, but **a value asserted on such a slot scores −1 and enters the pair's denominator** (v5.3, GPT-6 Q2: under v5.2 those assertions had zero fitness cost below a DQ-only ceiling — GoldNullAssertionRate stays the DQ-only gate); lifecycle enums (`event`, `stance`) are excluded from FQ and policed by the LifecycleErrorRate gate — so FQ measures exactly one thing: *did the arm fill the fields the source actually states, correctly*. Per field (v5, R3-F7 — the utility is FROZEN, and the scores are derived from it): accepted value **+1** · null **0** · wrong value **−1** — i.e. *a value is asserted only when it is more likely right than wrong* (break-even p* = 0.5). v4's −0.5 for null put the break-even at p* = 0.25: any field guessable at better than one-in-four was worth guessing, which in a memory product is backwards — a wrong deadline costs more than a gap. All-null optimization is blocked by the **FieldFillRate floor** (§7.4), not by penalizing honest gaps. **FQ_pair = (weighted mean + 1) ÷ 2, linear to [0, 1], NO clipping.** Worked micro-example: an all-null arm scores (0 + 1)/2 = 0.50 on FQ but fails the FieldFillRate floor → GATE_FAIL; an honest arm at 80% correct / 15% null / 5% wrong scores (0.8 − 0.05 + 1)/2 = **0.875**. Missing key ≡ JSON null; empty string = field violation → `MalformedFindingRate`. **Void below 20 aggregated matched pairs** — per §7.1's availability rule. Per-field weights frozen in criteria (default equal, none above 0.35; per-kind critical fields — deadline, amount — **carry frozen fill-floors** (v5.3: without them a null-heavy strategy fills three easy fields, omits every deadline, keeps FQ 0.875 and loses only 2.5 points)); the report carries the per-field table (value-supplied F1), fields ≥90% one gold value reported separately as trivially predictable. A wrong-but-span-grounded value is −1 AND tallied in `GroundedWrongFieldRate`.
- **EmptyHonesty** = inputs with zero gold findings of kind K where the arm's outcome is honest-empty ÷ all kind-K-empty inputs in the scored split-cell. **Honest-empty is defined per input (v3, F4 clarification):** either the input was routed and the arm emitted zero findings of K with `coverage == complete`, or **the input was never routed at all** — the scout's correct filter is honest end-to-end behaviour and earns credit (resolving v2's contradiction between the coverage requirement and the scout-filter award). `coverage != complete` never earns. Kind-level, not "globally empty emails". Architecture-specific cap budgets and coverage behaviour are **measured, deliberately not neutralized** — they are real production properties of the arm (Codex ruling on F4). **Denominator policy (v3, F15):** EH is VOID below 20 kind-empty inputs in the split-cell — arm-independent, resolved at freeze by the §5 census. Kept in the composite at 0.10 (dispersion Precision cannot see: five lightly-poisoned inputs beat one heavily-poisoned at identical precision), with its realized between-arm range printed beside the weight. The ~100 curated hard empties are a **separate diagnostic slice** (`EmptyHonesty_adversarial`), never averaged into the main figure. **Coverage honesty (v5.1; BINDING since v5.3 — GPT-6 F9):** a reported-only diagnostic left the dominant strategy intact ("`complete` on scored inputs, honest on the recognizable fixtures"). `CoverageHonesty` is now an **ELIGIBILITY requirement** (§7.4): on the frozen construction-known coverage cases (truncated bodies, window-limited context — covering routed AND `NOT_ROUTED` outcomes), `coverage != complete` is the correct answer and earns EH, a false `complete` fails the requirement, harness-known truncation overrides the model's claim for both architectures, and a correct required qualification is excluded from AbstentionRate violations. **`NOT_ROUTED` earns ordinary EH only when the input is assessable under the same coverage contract used for routed outputs** — otherwise the scout architecture collects credit the combined-pass architecture cannot, worth up to 10·q cell points at insufficient-input share q.

### 7.4 Gates & the eligibility state machine (v4 — THE single normative source; §7.1/7.5/7.7 reference it, never restate it)

*(v4, 2026-08-30: round 2 showed the v3 restatements — §7.1's "never reaches the table" vs §7.4's BORDERLINE — were themselves the defect generator. One state machine now governs.)*

**Arm states, per ranking claim:**

- **PASS** — every gate's point estimate passes at its declared scope. Fully rankable.
- **GATE_FAIL** — an **ELIGIBILITY-family gate's point estimate fails** (see *Eligibility family*, v5.1) and its interval straddles the threshold. The arm is **scored and printed normally, with the failing gate and interval named, but is INELIGIBLE for WINNER and for validation** (this restores §7.1's non-severability that v3's BORDERLINE quietly severed: a P = 0.45 arm is never a winner, no matter what the interval says). A point-estimate violation on a **DQ-only** gate does NOT change the arm's state — it prints as a diagnostic.
- **VOID** — arm-caused unavailability of a required component (e.g. too few summed matched pairs for FQ): `ArmScore_cell = VOID`, overall scalar VOID, ineligible, excluded from the TOP SET, computable components printed — never a reweight, never a dropped cell, never scored "normally" (v5.1: §7.1 and v5-§7.4 had described this one case as two different states).
- **DQ** — a gate fails AND its interval lies **wholly on the failing side** (sidedness declared per gate). Whole-arm: reported in the DQ section over the full frozen roster, never a low row.

**Terminal semantics (v4, R2-F11 — no state is open-ended):** report outcomes are `WINNER / STATISTICAL TIE / BELOW PRACTICAL DELTA / NO ELIGIBLE WINNER / VOID / DQ`. If the top-scoring arm is GATE_FAIL, it cannot be WINNER; the release's single resolution path is **one additional pre-registered, budget-charged batch** after a declared config fix — if no eligible winner emerges, **NO ELIGIBLE WINNER** is the release's final verdict (a legitimate, printable outcome — the founder decides what to build next from a fully-scored table, and "every arm GATE_FAIL/DQ" is itself a finding about the model class, not a failure of the measurement).

| **Recall_state_changing (v5, R3-F5)** | ≥ 0.70 **per event FAMILY**, rare families (cancellation/withdrawal) pooled across kinds and languages | v4's per-kind pool let an arm miss EVERY cancellation and still post 95.5% (40 of 896 events); an under-floor family is `NOT_EVALUABLE` or an enriched frozen slice — never silently pooled away |

**Eligibility family (v5.1 — reconciles §7.4 with §7.8 req. 3, which contradicted it):** two gate families, declared per row. **ELIGIBILITY gates** — Precision floor · Recall floor · FieldFillRate floor · LifecycleErrorRate · CoverageHonesty — **each evaluated ONCE per arm on arm-level pooled counts** (v5.3, GPT-6 F5: v5.1's "four gates" were four *names*; with per-cell P/R floors the family was 2C + 2K ≈ 30 scoped decisions, and a compliant arm at P = 0.60 was falsely ineligible somewhere with 42–62% probability — per-cell floors are now DQ-only) — decide GATE_FAIL on their **point estimate**: eligibility is a policy precondition for the WINNER claim, not an inference claim, so a false ineligibility is conservative (it withholds a winner, prints the margin, and can be resolved by the resolution batch above). **DQ-only gates** — G1b · G2 · per-cell score floors · per-cell Precision/Recall floors (v5.3) · AbstentionRate · SpanUngroundedFieldRate (v5.2) · GoldNullAssertionRate · GroundedWrongFieldRate · Recall_state_changing — never change eligibility on a point estimate; they DQ only when interval-confirmed, and print point violations as diagnostics. *Why the family must be small and point-tested: an interval-based eligibility test (Codex, round 3) lets the coward arm through — at effective n = 50–150 the one-sided upper bound on R = 0.35 is 0.41–0.46, above the 0.40 floor, so §7.8's own acceptance line (2) would fail; while point-testing all ~15 gates false-fails a compliant arm most of the time (Codex, ~0.75). Five arm-level point tests on pooled denominators confine false ineligibility to arms within ~1.5 SE of a floor — arms that are borderline unusable anyway; even so, five tests each 1.5 SE inside their limits have a 24% joint false-fail rate, so the family's actual DECISION COUNT and joint false-ineligibility operating characteristics (with gate dependence) are computed and printed at freeze — no universal "≤ 5%" is claimed (§7.8 req. 4).*

**Constant calibration (v5.1 — closes a contradiction):** the four gates whose ceilings are "recalibrated against the ceiling arm" (G1b, GoldNullAssertionRate, GroundedWrongFieldRate — NOT SpanUngroundedFieldRate, whose ceiling is absolute, v5.3) cannot both be declared before any arm runs and be derived from an arm's results. Resolution: **one pre-registered CALIBRATION run** of the ceiling arm on the **optimization split**, executed BEFORE the criteria file is frozen; each ceiling = the calibration rate + a declared margin, frozen together with the calibration run's config hash; the calibration run consumes no hidden-split budget and is **excluded from every ranking** (the ceiling arm is re-run afterwards as an ordinary ranked arm). The ceiling model's behaviour still defines the bar — but once, in the open, before any small arm is scored.

**Micro-pooling, defined once (v4, R2-F5):** "N=3 pooled counts" = matching run independently per run, then numerators and denominators **summed across the three runs** — never replicate predictions concatenated into one input, never per-run ratios averaged. The pooled gate statistic prints beside every gate decision. (The arm's SCORE is a different statistic — the mean of its three complete-run scores, §7.6 — deliberately so.)

**Decision mechanics (v4):** every gate row declares its **split source** (which hidden split supplies each decision-capable statistic — frozen at release, R2-F1). Rate gates pool arm × kind (language cells pooled, denominator ≥ 50; below 50 → arm level; per-cell rates print as diagnostics). Intervals use the ONE named estimator of §7.7 (percentile-t cluster bootstrap; **sidedness declared per gate row**; v5.3 withdraws the i.i.d. exact-binomial wording — bounds for clustered, run-repeated counts come from the §7.8 estimator). **DQ family control (v5.3, GPT-6):** the DQ gates form a declared family — each row states a materially-unacceptable alternative rate and its required power, and the family error is allocated across the declared DQ decisions (Bonferroni at our scale); twenty individually-valid 95% gate intervals would otherwise produce a false DQ 64% of the time. A required-but-`NOT_EVALUABLE` gate never reads as passed. **Precedence, total over the grid (v5, R3-F11; v5.1 family-qualified): interval wholly failing ⇒ DQ (any gate); otherwise point-estimate failure on an ELIGIBILITY gate ⇒ GATE_FAIL; otherwise PASS (a point violation on a DQ-only gate prints as a diagnostic and leaves the state unchanged)** — and the point and interval estimands are the SAME statistic at the same aggregation (a pooled-count gate is judged against the interval of that pooled count; the mean-of-runs score against its own interval — never one against the other); **BORDERLINE as a state is withdrawn** (it severed the floors' non-severability and had no terminal semantics). Point-estimate-only gates at these n would false-DQ compliant arms with near-certainty (a true-1% arm trips some 25-pair cell of ten with p ≈ 0.92; an exactly-at-target scout passes ten 20-case cells with p ≈ 0.047 — Codex-verified), which is why the interval decides DQ and the point estimate decides eligibility.

**Frozen roster (v3, F1 — unchanged in v4):** the scored-cell roster is **frozen from gold eligibility alone and is identical for every arm**; no arm-dependent quantity (gate outcome, matched-pair count, prediction count, parse failures) ever adds or removes a cell from any arm's aggregate. DQ'd and GATE_FAIL'd arms are reported over the full frozen roster. An arm can never improve any aggregate by failing or by emitting nothing (v2's cell-exclusion wording let an arm gain +4.8 mean by destroying its weakest cell — withdrawn). **The production-fitness orientation (P ≥ 85% / R ≥ 75%) stays a founder guideline over the report, not a measurement gate.** Scout objective is lexicographic (anti-route-everything): first recall ≥ 95%, then minimize routed fraction / specialist calls per 1,000 inputs; the recall-vs-routing Pareto frontier is reported.

### 7.5 Aggregation & floors

- **Cell** = kind × language, on a **complete common language grid (v5, R3-F6):** the criteria file freezes an operational language classifier and a **prevalence cutoff above which every language class — including `mixed` — is a REQUIRED cell for every scored kind**. The balanced headline is computed **only over kinds present in every required language** (kind-first averaging on an asymmetric roster silently weighted BG 2:1 over EN — a 6.7-point mirror-arm artefact); kinds available in one language only go to a **scoped annex** and their result is named for what it is (`ColonyScore_bg`). Realized cell and language weights print in every report. Micro over all findings is a secondary column. **Overall = unweighted mean over the kinds on the common grid.**
- **Roster (v3, F1):** the scored-cell and scored-kind roster is frozen from **gold eligibility alone** at freeze, identical for every arm, printed in every report. Gold-insufficient cells are VOID for all arms symmetrically and NAMED; a void required cell voids the ranking claim built on it. (v2's "or DQ'd" exclusion is withdrawn — DQ is whole-arm, §7.4.)
- **Floors (v4, F2 + R2-F7 — two DIFFERENT kinds of floor, never conflated):** (a) the **raw availability floor** — per-cell gold ≥ ceil(20 ÷ RecallFloor) = 50 findings per scored split-cell (derived from FQ's 20-matched-pair minimum at the Recall floor for a SINGLE run — the availability rule counts the summed N=3 pairs, so this is conservative by design; the constants move together) — this makes components computable; it says nothing about inference. (b) the **inferential requirement** — the criteria file preregisters a **planned design effect and a power target** (e.g. DEFF 1.8, 80% power against PracticalMinimumDelta), raw counts are derived as n = n_eff × DEFF, and a **per-cell minimum of independent leakage groups (≥ 15)** is enforced beside the finding count. A cell can clear (a) and fail (b) — it is then computable but its claims print with their actual resolution, per §7.7.
- **Headline & ranking scalar (v4, R2-F4 — the min-cell scalar is withdrawn):** **the ranking scalar is the overall unweighted mean across scored kinds** (language-balanced, over the identical frozen roster); the weak-slice protection the minimum provided now lives where it is statistically sound — in the **simultaneously tested per-cell score floors of §7.4** (a broken cell makes the arm ineligible instead of biasing its rank). *Why withdrawn: a raw minimum of K noisy cell estimates is a selected statistic, biased downward by ~3.8–7.7 points depending on K and σ, with a measured 40.7% probability of inverting a true ranking at K = 10 — and the paired delta between two arms' minima is ill-defined when their argmin cells differ (Codex-verified, round 2).* The headline prints as the triple **(mean, minimum cell + which cell, per-language means)** — the minimum stays VISIBLE with a bias note, it just no longer orders arms. Flags unchanged: **UNBALANCED** (max cell − min cell > 20), **LANGUAGE-SKEWED** (|mean_bg − mean_en| > 10 — disqualifies any bilingual claim). `Recall_state_changing` and `FQ_state` are now gates (§7.4), no longer mere diagnostics.
- **Sizing is DERIVED, never asserted (v4, F12 + R2-F3):** required gold = **number_of_scored_splits × Σ over frozen cells of the per-split cell floor** (stated so the 3× multiplier is unambiguous: 3 splits × 50/cell = 150 per cell TOTAL, not 450), recomputed and **printed at freeze; the freeze FAILS if any required split-cell is short**. The v3 order-of-magnitude figure (~1,000–1,500 for the full grid) and all corpus percentages in this standard are **provisional, single-sourced observations — the versioned census instrument re-establishes every one of them at freeze**. **The census is an INSTRUMENT, not a script someone ran once (v4, R2-F3):** its lexicons, language classifier, and dedup rules are versioned and hashed into the release; the **language axis is defined operationally on ANT-visible, quote-stripped content** (naive both-alphabets measures put mixed at 80–86% of this corpus — operator-reverified 2026-08-30 — so the mixed-cell decision is unavoidable and is made in the criteria file BEFORE sampling); it reports **candidate leakage groups AND an estimated candidate→gold yield factor** (marker hits are not findings); the complete frozen cell grid with per-cell counts is published in the manifest. **Feasibility inequality — THE single source for the threshold (v5, R3-F14):** a cell is feasible iff `candidate_groups × LCB(yield) ≥ margin × scored_splits × gold_floor_per_split` AND it meets the independent-leakage-group minimum — where `yield` is the measured candidate→gold conversion (published with its sample and interval; at yield 0.5, 150 candidate groups predict only 75 findings, not 150). A cell that fails is **OUT OF SCOPE at design time** — removed before sampling, named in the manifest, the report banner scoping the claim (the one exception to the void rule, decided before any arm runs). Provisional census: operating-rule × en ≈ 43 candidate groups → expected out of scope.
- **Statistical figures (v3, F14):** the ±12.7/±9.5/±7.3/±5.2 half-widths quoted in v2 were i.i.d. binomial recall intervals, not intervals on ArmScore — **withdrawn**. Every interval in this standard is the §7.7 cluster-bootstrap interval on the composite; the design effect is measured on the actual leakage groups at freeze and all sizing uses n_eff = n ÷ DEFF.
- Secondary view: a production-prevalence-weighted score with weights frozen from an independent corpus audit (never from the curated gold sample). Reported beside the balanced view, never merged.

### 7.6 Ranking protocol — where each number is computed

- **fixed_interface** (identical prompts/schemas across models; diagnoses transferability): run on the **optimization + test splits only, exactly once per release** (v3, F5 — v2's "entire gold set" would have scored every arm on validation before selection, destroying the one-shot winner-only rule the same section states; "entire" is withdrawn). Nothing is tuned in this mode, so blinding the TEST split buys nothing — that carve-out stands — but **validation's value is that no arm has ever been measured on it**, which no power argument overrides. The run **consumes its arm count in test-budget units** (v5.1 — the budget bullet below is authoritative; "one unit" was a v4 leftover); its score is computed **once over the pooled optimization + test inputs and labeled `opt+test`** in the provenance column (pooling is the point of the mode), per-split numbers printed beside it as diagnostics; per-case reports stay in the hidden root; stdout stays aggregate.
- **deployment_optimized** (per-model tuning under an equal pre-declared budget, optimization split only): tuned AND ranked on the **optimization split**, absolute scores honestly labeled tuning-inflated; the hidden **test split is used for rank-order agreement only** — one preregistered question with a NAMED procedure (v4, R2-F13): a **one-sided paired non-inferiority test** on the (test − optimization) paired difference of the top arm's delta, at margin PracticalMinimumDelta, from the joint bootstrap. Kendall's tau prints as a descriptive beside it (with K, step size, and expected discordance under a true ranking — never as a pass/fail).
- **Validation protection (v3, F5):** the runner **refuses `--validation`** unless the invocation names exactly one arm, that arm's config hash matches a frozen winner declaration, and that arm has never previously been scored on validation (integrity error, exit 2, otherwise). Any arm ever scored on validation is thereafter ineligible to be the validated winner.
- **Bake-off discipline (Codex):** candidates preregistered and frozen (config hashes) before any test-split scoring; no mutation after the ranking checkpoint; **validation runs once, on the single selected winner only** — validating multiple arms turns validation into a second selection split and would demand a fourth holdout.
- **Test budget (v4, R2-F13 — the adaptive unit is the ARM, not the batch):** one unit = **one arm's score released from one hidden split**; a batch may carry at most 10 preregistered arms and costs its arm count; budget = **30 units per release lifetime, printed `n/30` in every result** (a batch metered as 1 released ≥10 adaptive queries — Dwork-style degradation counts information releases, and arms are the releases). fixed_interface consumes its arm count. Burned budget ⇒ test scoring stops until a gold extension. The counter lives outside editable paths, increments BEFORE execution, records config hashes including failed/cancelled attempts, and **every hidden-split use prints the split's minimum detectable effect beside its result** (at n≈90 the 80%-power MDE is on the order of 15+ points — printed so nobody reads a 5-point test-split gap as signal).
- **N=3 policy (v3, F14 — the scored statistic is now defined):** **the arm's point estimate is the arithmetic mean of its three complete-run scores**; all three runs, range, and flip-rate print beside it and no other statistic is reportable as the arm's score. **A voting configuration is a distinct ARM** — its merge rule lives in its config hash, N=3 applies on top (9 calls), metered accordingly; "field-wise vote-merging is fabrication" forbids merging at *scoring* time, not the evaluation of a declared voting arm (this is how the does-voting-pay question gets answered without circularity).
- **Noise floor (v4 — `NoiseFloorSigma` WITHDRAWN as a winner condition, R2-F12):** Codex: a release-level noise constant with no defined reference arm or paired scale was a redundant hurdle on top of the paired bootstrap interval + PracticalMinimumDelta, which already gate. Same-config run noise is still measured — on the **optimization split, where repeats are free** — and reported as a diagnostic; §10 defense 6 now reads on that measurement.
- **Resolution reality (v5.3 — REPAIRED simulator, 2026-09-06; exploratory, NOT power certification):** on synthetic gold averaging ~130 findings / ~34 leakage groups per draw with N=3 and exact per-run F_0.7, a singleton TOP SET reaches 52% at a 3.9-point true gap, 71% at 5.3 and 82% at 6.4; a **WINNER at PMD = 5 is declared 16% of the time at a 6.4-point gap** (v5.2's F1-based table was more optimistic); the observed order of two arms inverts 18% of the time at a 1.6-point gap and ~1% from 4 up; the global null produced 0 false winners in 120 draws (one-sided 95% upper bound 2.5% — not a proven zero). **A WINNER claim at a true gap equal to PMD can never reach 80% power — it is the null boundary**; sizing must distinguish testing Δ > 0 from Δ > PMD and declare an alternative Δ_alt > PMD. Planning scenario for Phase-1 sizes (500–750 findings per split, DEFF 1.5–2, GPT-6): 80%-power WINNER needs true gaps of ≈ 8–10 points (two arms) or 9–10 (ten arms). Power is re-computed for the frozen conforming scorer on the actual grid before freeze; these numbers are not it. Weight perturbations of ±0.1 reorder the mid-pack by 1–2 places, inside that noise; the top arm is stable.
- **PracticalMinimumDelta (v3, F14):** a **numeric frozen constant in the criteria file, declared by the founder at gold freeze** (v3 default: 5 points on the ranking scalar); changing it after any score is visible invalidates the ranking.
- **Cost & latency** (unchanged): metered (raw usage × versioned price sheet, incl. retries, repeats, failed calls), side-by-side columns, never blended into the score.
- Weights and gate constants are **v5.2 constants** — recalibrated only against re-scored historical runs so rankings stay comparable (the PR document's closing rule, adopted verbatim).

### 7.7 The report template (forced, not advisory)

Every ranking row shows: **n (the actual denominator) · all three run scores · range · flip-rate · 95% CI**, and the component columns beside every composite: R · P · F1 · FQ · EH · AbstentionRate · SpanUngroundedFieldRate · GoldNullAssertionRate · GroundedWrongFieldRate · FieldFillRate · StateInversionRate · Recall_state_changing (per family) · DuplicationRate · MalformedFindingRate · ParseFailureRate · G1b rate · routed fraction · per-language means · realized cell weights · span diagnostics (SpanBreadth = median len(pred)/len(gold) · WholeInputSpanRate · PrimarySpanStability across the N=3 repeats). **The inference layer is implementation-defined and empirically accepted (v5, R3-F12/F13 — supersedes v4's named-estimator prose, which Codex showed was not implementable as written: one global resample SD makes a "percentile-t" algebraically a basic bootstrap, and exact binomial bounds are invalid on leakage-clustered, run-repeated model outcomes).** This standard no longer prescribes the algorithm in prose; it prescribes **requirements** the scorer must meet and a **binary acceptance test** that proves it does — §7.8. Component intervals are never combined; **G (independent leakage groups) is defined at each statistic's own scope**, prints beside every interval, and **G < 15 for a required statistic is a FREEZE FAILURE**. A **split-provenance column on every number** — an optimization-split score and a test-split score never share a column. **Selection over the arm family is controlled (v4, R2-F6 — under a global null the v3 pairwise walk crowned a false WINNER ~31% of the time at 10 arms):** within the same bootstrap resamples, compute the **max-t adjusted paired deltas across the frozen arm family**; the primary selection artifact is the **TOP SET** (multiple-comparisons-with-the-best: every arm whose adjusted delta to the best fails significance is in it); descriptive tiers below the top set are labeled NON-TRANSITIVE. Every comparison carries a forced **outcome label**: `WINNER / STATISTICAL TIE / BELOW PRACTICAL DELTA / NO ELIGIBLE WINNER / VOID / DQ`. **WINNER requires: the top set has exactly one member AND that arm is ELIGIBLE (§7.4) AND, on UNROUNDED values, the max-t simultaneous lower confidence bound of its paired delta exceeds PracticalMinimumDelta against **EVERY eligible competitor — `min over j ∈ E∖{r} of LCB_max-t(S_r − S_j) > PMD`** (v5.3, GPT-6 F7: the runner-up-only test crowned a winner whose lead over a high-variance third arm was unproven — LCB 5.5 vs the runner-up but 2.0 vs the third arm; the observed-runner-up comparison stays a report column)** (v5, R3-F2 — one inequality, so no implementer reads the two conditions as separable; the comparison family is ELIGIBLE arms only, ineligible and DQ arms in their own counterfactual tables) — otherwise the label is a tie. Choosing the cheaper tied arm is a valid operational decision that must never be described as higher model quality, and cost may break a tie only when the tied arms' span diagnostics are comparable (a wall-of-text arm never wins on price). Scores print to whole points (78.43 manufactures precision the data cannot support). The report opens with one worked example — a real input, its gold, and each arm's verbatim output — before any table, and carries the standing banner at the top: finite-set conformance on THIS organization's email; "MEASUREMENT COMPLETE" ≠ "the model is good". The cost trade is stated per adjacent pair as a sentence ("X is 3 points above Y — CIs overlap, tier 1 — at 4.2× metered cost per 1,000 inputs"), never left to mental blending.

### 7.8 Scorer conformance — the inference layer is proven by test, not by prose (v5)

*Three adversarial review rounds (11 → 12 → 11 significant findings; ~15M subagent tokens) showed that every round's statistical amendments generated the next round's defects. The 70/20/10 formula, matching, components, gates, and state machine are frozen as written above. The inference layer — how intervals, multiplicity, and gate decisions are computed — is specified below as REQUIREMENTS plus one binary acceptance test, and no further prose review is scheduled: the harness is the verifier.*

**Requirements any conforming scorer must satisfy (from Codex's round-3 rulings, R3-F1/F9/F12/F13):**
1. Intervals come from a **studentized hierarchical cluster bootstrap** — leakage groups resampled with **shared indices across arms**, run effects resampled independently per arm unless seeds are genuinely paired, a **per-resample nested/jackknife SE** (never one global resample SD), and the statistic recomputed in every replicate **exactly as scored** (mean of three complete-run scores; pooled counts for count gates). **The named algorithm (v5.3, from GPT-6's outline — frozen in the criteria file with its bootstrap counts, quantiles and degeneracy rules):** (i) match per run and input, compute each run's score on the identical cell grid, average the three; (ii) apply availability and eligibility, keep every computable arm in the report; (iii) resample leakage groups with replacement, shared across arms, each group carrying its complete inputs and cells; (iv) resample whole-run effects per arm as a crossed dimension — three complete run vectors drawn per arm and applied across all resampled groups, never redrawn inside each group; (v) recompute the full statistic vector per replicate and pick the reference-best inside the replicate with a frozen tie-break; (vi) studentize every pairwise delta per replicate with an inner resample or validated jackknife; (vii) all-pairs single-step studentized max-t with an MCB projection — critical value = the 1−α quantile of the two-sided maximum, simultaneous lower bounds L_ij = Δ̂_ij − c·ŝ_ij; (viii) TOP SET = {r} ∪ {j : L_rj ≤ 0}, decisions on unrounded values; zero eligible arms ⇒ NO ELIGIBLE WINNER, one ⇒ reported, never a comparative WINNER. Validity needs independent leakage groups, adequate informative clusters, stable ratio denominators and a fixed comparison family; at G ≈ 15–30 a few groups can dominate, rare-error gates can have zero studentizers, and three runs say little about whole-run variance — the conformance suite below tests exactly those regions.
2. **Multiplicity:** the comparison family = ELIGIBLE arms only; one complete single-step max-t / MCB algorithm, named in the criteria file, with the reference-best selected inside each resample, the studentizer stated, and decisions on unrounded simultaneous bounds; outcomes defined for family sizes 0 and 1; `k` and the critical value printed.
3. **Gate family control (v5.1 — now consistent with §7.4):** the complete gate family, scopes, and the ELIGIBILITY / DQ-only classification are frozen before any ranked arm runs; the criteria file's gate table carries LITERAL columns `scope · split source · denominator · N=3 statistic · sidedness · family`, and each gate is classified count-gate or score-gate. **Eligibility (GATE_FAIL) is decided by the point estimate of the four ELIGIBILITY gates only** — a policy precondition, not an inference claim; point violations on DQ-only gates are printed diagnostics. **Confirmed failure (DQ) is interval-based for every gate**: ceilings need the lower bound above the threshold, floors the upper bound below it. (Codex's round-3 proposal to make eligibility itself an interval test is withdrawn: at effective n = 50–150 it keeps a coward arm at R = 0.35 eligible, failing acceptance line (2).) **i.i.d. exact-binomial bounds are withdrawn** for clustered, repeated outcomes.
4. **Power at freeze:** the familywise false-ineligibility rate of the ELIGIBILITY family (five arm-level point tests, with their dependence) and the power of every DQ gate against its declared alternative are computed at clustered effective denominators BEFORE freeze and printed in the release; a gate lacking the required power triggers data growth or `NOT_EVALUABLE` — never silent operation at the raw denominator. Raw and independent-cluster denominators print side by side.
5. **Acceptance ≠ conformance (v5.3, GPT-6 F6):** passing the suite alone does not establish conformance — a scorer that prints zero-width intervals and declares WINNER whenever the observed lead exceeds PMD passes the null test (0.0014% false winners in 500,000 five-arm null draws) yet declares WINNER ~50% of the time at a true gap of exactly PMD, and an inflated self-reported MDE lets it pass the power line too. Conformance = the frozen named algorithm of req. 1 + the full suite including lines (8)–(12).

**Acceptance — one line, binary, run by the founder (per §9's trust chain):**

> `SCORER ACCEPTANCE: 12/12 PASS` ⇔ (1) a synthetic **spam** arm (Recall 1.0, Precision 0.45) is ineligible; (2) a synthetic **coward** arm (Precision 1.0, Recall 0.35) is ineligible; (3) a synthetic **state-inverter** (correct spans, lifecycle family flipped) is ineligible — lines (1)–(3) are decided by the ELIGIBILITY family on point estimates (§7.4), which is why they are deterministic; (4) a synthetic **known-good** arm is the singleton TOP SET in **≥ 80% of ≥ 1,000 simulated gold draws at true gap = the printed MDE, and in ≥ 95% at 1.5 × MDE** (v5.1 — "whenever the gap exceeds the MDE" was unpassable: 80% at gap = MDE is the definition of an 80%-power MDE); (5) under a **global null** (all arms identical) a WINNER is declared in ≤ 5% of ≥ 1,000 simulations; (6) every §7.2 conformance fixture passes (gold-self-match = 1.0, identical-span/field-distinct, objective steps 2–3, semantic-duplicate pruning); (7) a synthetic **selective-spam** arm (Recall 0.98, Precision 0.62 — junk only on non-empty inputs, so it clears every floor) **ranks below the honest reference arm** (v5.2: under β = 1 it out-scored honest by up to 2.6 points in simulation — re-confirmed on the repaired simulator, 76.9 vs 74.6 at β = 1 reversed to 73.7 vs 75.6 at β = 0.7 — the one failure mode the gates cannot catch, so the ranking must); (8) **simultaneous-bound coverage** ≥ 95% under global AND partial nulls over ≥ 1,000 simulated gold draws; (9) **practical-margin boundary**: at a true gap exactly equal to PMD, WINNER is declared in ≤ 5% of draws; (10) **degenerate cases** — heterogeneous pairwise variances, concentrated cluster errors, zero studentizers, and the `(0, 30, 30)` matched-count arm — resolve to the specified states, never to a number; (11) a **sole eligible arm** is reported, never declared a comparative WINNER; (12) **matching fixtures**: two-occurrence gold-self-match = 1.0, unrelated-half-of-envelope ≠ match, right-family/wrong-code counted by LifecycleErrorRate.

Synthetic arms are generated from the frozen gold with declared corruption operators, so the test needs no model calls and runs in minutes. A scorer that fails any line is non-conformant regardless of how elegant its statistics read; a scorer that passes is accepted even if a reviewer would have chosen a different estimator. **This replaces further review rounds.**

"Per kind" means per SET for Phase 0. Once a verdict line has been printed, any further `--validation` attempt on the same lock is exit 2 permanently, and a printed verdict not attributable to the founder REVOKES the lock: its holdouts are consumed and a fresh labeled holdout plus a superseding lock are required (§1.3). A flag check plus an audit entry cannot prove who invoked the runner — §13's interim OS-level wall (hidden root owned by a separate account / founder-owned runner service) is the recommended upgrade and stays parked as v1 hardening.

## 9. Trust chain for /goal (the circularity fix)

*Codex blocker #1: a goal that may edit its own verifier can print any PASS it likes.*

1. **The runner and the criteria file live OUTSIDE the /goal-editable paths.** Goal conditions enumerate editable directories; the verifier is never among them.
2. **The release-lock hash is pasted literally into the /goal condition text** — the evaluator can at least compare the echoed hash string.
3. **A /goal PASS is provisional.** Final acceptance = the founder personally re-runs the runner once (minutes). At our scale, the founder's own run IS the external root of trust — signed locks, KMS keys, and attestation infrastructure are parked (§13).
4. Phase-1's binary verdict means **"MEASUREMENT COMPLETE: all arms and repeats present"** — never "model quality passed". Model choice is a founder decision over the report.

## 10. The formula as an optimization target — and the anti-Goodhart contract

A formula makes quality **optimizable**: mutation loops (anchor edits, prompt phrasings, thresholds, model swaps) accept changes only when the score rises; `/goal` can drive such loops ("raise ColonyScore on the optimization split by ≥5 points without breaking any gate"); and a red-team loop attacks in the reverse direction — every found failure becomes a new gold case, the score drops, the fix loop pushes it back.

**Goodhart's law is the standing threat: when the number becomes the target, systems learn to optimize the number.** The six defenses (all proven in this project's earlier optimization loops — reader 12.1% → 24.2% under this exact discipline):

1. **Optimize against the optimization split only** (v1.1) — the test split is scored blind at accept-checkpoints through the runner; the validation split is touched once, at final acceptance, by the founder.
2. **Independent verifier audit on every accepted improvement** (isolated context, artifacts only): is the gain real, or did the prompt specialize to the gold? Verdicts CLEAN / SUSPECT / GAMED. The audit also scans the transcripts for any attempt to reach the hidden root (§10a's tripwire).
3. **Gates are non-compensable** — no score buys back a fabricated quote or lost content.
4. **Anti-bias rule:** no corpus or gold literals in prompts/anchors/schemas — verifier-audited.
5. **Frozen manifest + criteria + `runner_sha256` in the lock, runner outside editable paths, founder run from a clean checkout (§8 item 1a)** — editing the exam is detected, not merely forbidden; an OS-level wall is parked (§13).
6. **Noise floor:** accept only deltas larger than same-config run noise, **measured on the optimization split where repeats are free** (v4 — the release-level `NoiseFloorSigma` winner condition is withdrawn as redundant with the paired interval + PracticalMinimumDelta; this defense governs the MUTATION loop's accept rule, not the ranking).

### 10a. Mechanical blinding (v1.1, 2026-08-29 — founder requirement)

Blindness to the test/validation splits is enforced **by construction, not by policy** — the same doctrine as RLS-under-the-model:

- Hidden splits live under `Benchmarks/_mem01_hidden/` — **outside the agent workspace** (§3).
- `settings.json` permission **deny rules** on Read/Grep/Glob for that root: the optimizing agent cannot open, search, or list the cases. The runner (a separate process the agent merely invokes) reads them itself.
- Score feedback is throttled, not just the cases: aggregates-only stdout (§8.7), checkpoint-only test scoring, and the persistent `test_evaluations_total` counter — a blind score run after every mutation is still a leak channel (leaderboard overfitting), so evaluation frequency is itself budgeted and visible.
- **Honesty clause:** deny rules block the file tools, but an agent with shell access could still read the files — this layer is a *tripwire*, not a cryptographic wall. Defense-in-depth = outside-workspace placement + deny rules + verifier transcript audit for circumvention attempts + founder-run validation. A cryptographic seal (encrypted hidden splits, key held only by the runner) is parked in §13.

## 11. Versioning & comparability

- **Immutable core + extension slices:** `step1-v2 = core-v1 + bugs-v2 + new-cells-v2`. Every v2 report shows: the core-v1 score (directly comparable with old runs) · each extension slice separately · the full v2 score. **Never compare v1 and v2 aggregates directly** — the mixture changed.
- Production bugs land in a visible `regression` extension (origin-tagged), not silently in the core; extensions are periodically promoted into a new balanced core.
- Raw per-record predictions are preserved so new metrics can be recomputed later.
- Run identity for any reported number: `release lock × criteria version × harness version × model/endpoint fingerprint × prompt/config version × repeat policy`.
- **Two exceptions to append-only:** (a) label/input corrections create a superseding release and invalidate prior results on affected records; (b) lawful PII erasure removes records entirely — the prior release is marked revoked, comparisons continue on the surviving intersection (consistent with pipeline §11.9).

## 12. What gold JSONL does NOT replace

Property/metamorphic tests, concurrency and fault-injection tests, RLS negative suites, and load/latency testing are separate test forms (already in the phase plans). External validity is limited honestly: this corpus proves performance on THIS organization's email — new clients/domains get a calibration pass, not blind trust.

## 13. Parked — v1 hardening (right-sized out of v0, recorded so it isn't lost)

Signed release locks with external key custody (CI/KMS) and runner attestation · population-grade certification (≥300-case zero-failure sets for <1% claims at 95% confidence) · sampling weights / production-prevalence reporting · formal sequential testing (alpha spending, anytime-valid CIs) — v0 uses the practical form: tune on the optimization split → compare top-2 arms on the hidden test split, validation once · full TREC-style pooled qrels (v0 uses the post-hoc judgment rule) · encryption/ACL/access-logging on the gold store · cryptographic sealing of the hidden splits (encrypted at rest, decryption key held only by the runner's environment — upgrades §10a's tripwire to a wall) · OS-level ACL wall (hidden root owned by a separate OS account / founder-owned runner service, unreadable by the optimizing process — Codex's cheaper interim step toward the same wall).
