## 0. Vocabulary

- **Instrument** — code that measures. Lives in `backend/tools/mem01_verify/`, is frozen and hashed at the stage-B freeze (`runner_sha256`), and is OUTSIDE every /goal-editable path from then on.
- **Measured component** — product code the exam judges (quote stripper, chunker, language detector, noise classifier, extractors, threading, identity, redaction, embeddings, erasure). Stage A writes NONE of it. Where a measured component already exists (parser, extractors, `redact_secrets`, `parse_date`, the entity resolver, RLS policies), Stage A only observes it — and never uses it to compute an EXPECTED value.
- **Configured database** — the database `app.core.config.Settings` resolves to (today `one-ai-mvp-db-1`, 127.0.0.1:5432, holding the 5,893-email corpus in org `d1500000-0000-0000-0000-000000000001`). The instrument never modifies it.
- **Configured server** — the Postgres server that hosts the configured database. Probe databases are created there.
- **Probe database** — a disposable database the instrument creates from zero on the configured server, migrates to head, fills with synthetic fixtures, measures, and drops.
- **Corpus gate** — a gate whose evidence is the real corpus (C evidence, plus H labels later). Runs read-only, from one consistent snapshot, against the configured database.
- **Fixture gate** — a gate whose evidence is public synthetic fixtures (F evidence). Runs against a probe database, or in-process where no database is needed.
- **Release** — the directory `<gold root>/releases/<name>/` per gold-standard §3. Stage A produces a **draft** release; stage B cuts the **frozen** one.
- **Gold root / hidden root** — `Benchmarks/_mem01_gold/` and `Benchmarks/_mem01_hidden/` under the workspace's PARENT directory (`C:/Users/Yani_/Desktop/In-Progress/One AI/Benchmarks/`), overridable by environment variables `MEM01_GOLD_ROOT` and `MEM01_HIDDEN_ROOT`. Both are outside the repo. The hidden root is NOT created in Stage A (founder decision); every code path that would open it must behave correctly when it is absent.
- **Closure** — the complete declared set of inputs that identify a candidate: editable-scope code, dependency locks, declared configuration artifacts, the env allowlist, the applied migrations, the corpus digest, the fixture digest (§3.11).
- **Aborted run** — a run that ends before every gate reached a terminal status. It prints NO verdict line.
- **Completed run** — a run in which every gate reached a terminal status (`PASS`, `FAIL`, `ERROR`, `incomplete`, `skipped`). It prints exactly one verdict line.

Evidence letters as in the experiments doc: **C** corpus invariant, **F** conformance fixture, **H** labeled examples (H-optimization / H-test / H-validation).

## 2. Hard rules every instrument obeys

R1. **Lock first, in stages.** The runner verifies the release lock over the VISIBLE inputs before reading any data file or opening any database (stage 1), and verifies a hidden split only after that split's use has been authorized and durably reserved (stage 2). Mismatch at either stage → aborted, exit 2.
R2. **An error never shrinks a denominator.** A missing record, duplicate id, unexpected id, exception, unplanned parse error, cancellation, or partial run makes the affected gate ERROR and the run exit 2. Never PASS, never a smaller denominator.
R3. **A gate whose measured component or required evidence does not exist prints `incomplete`, never PASS.**
R4. **Aggregates only on stdout for hidden evidence.** Stage A has no hidden evidence, but the code paths for hidden splits already obey gold-standard §8.7 through the stdout projection of §3.4.
R5. **No personal data on stdout, ever.** Email addresses, names, subjects, bodies, filenames never appear in stdout or stderr. UUIDs and hashes may. Per-case detail goes to report files under the release (visible) or the hidden root (hidden).
R6. **Read-only and consistent against the configured database.** Every transaction the instrument opens on the configured database's tables is declared `REPEATABLE READ` and `READ ONLY` at the server, on every transaction including reconnects and transactions started after a commit or rollback (a write attempt is refused by the server, not by convention). The roster, the corpus digest and every corpus gate's evidence for one run are computed from ONE such snapshot; the snapshot's transaction identifier is recorded in the block; if evidence had to be taken from more than one snapshot, the corpus digest is recomputed at the end and any difference aborts the run. Probe-database lifecycle statements (`CREATE DATABASE` / `DROP DATABASE`) are the one carve-out: they run on the configured server's maintenance database (`postgres`), never inside a transaction and never against the configured database.
R7. **The instrument never trusts itself.** It recomputes `runner_sha256` on every run and prints it; the frozen value in a frozen release must match or the run is exit 2.
R8. **UTF-8 by construction.** stdout and stderr are UTF-8 regardless of console code page; the self-test (§3.9) proves it before any other output.
R9. **Versioned outputs.** Every emitted artifact carries a version tag (`MEM01_RESULT_V1`, `SNAPSHOT_V1`, `CORPUS_DIGEST_V1`, `EVID_NORM_V1`, `LEAK_GROUPS_V1`, `LANG_BOOTSTRAP_V1`, `CENSUS_V1`, `FIXTURES_V1`) and the hashes of its inputs.
R10. **House rules apply in full** (`.claude/rules/code-quality.md`, `security.md`, `testing.md`): file-level docstrings with Role / Used by / Depends on / Key invariants, every source file FEWER THAN 500 lines (target <300), typed signatures, custom exceptions only, no `Any` without a comment, no dead seams, descriptive names.
R11. **No verdict line on an aborted run.** A refusal or crash before every gate reached a terminal status prints the machine block with `status: ERROR`, `aborted: true` and a block-level `reason`, and NO verdict line. Only a completed run prints the verdict line, and only after cleanup and audit finalization (§3.2). (An aborted founder validation run is resettable exactly because no verdict line was printed — gold-standard §8 item 9.)
R12. **Expected values never come from measured components.** Fixture expectations and gate thresholds come from independently specified fixtures and frozen rules; the measured components (parser, extractors, redactor, date parser, resolver, policies) are only ever invoked to obtain ACTUAL results or to arrange state.

## 3. The runner — `verify_step1.py`

### 3.1 Invocation

Both forms must work identically:

```
python backend/tools/mem01_verify/verify_step1.py [options]     # from the repo root — the exact /goal form
uv run python -m tools.mem01_verify.verify_step1 [options]      # from backend/
```

Options (long names exactly):

| Option | Meaning |
|---|---|
| `--release PATH` | Release directory. Default: `<gold root>/releases/step1-gold-v1`. |
| `--expect-lock sha256:<hex>` | The lock the caller expects (the value pasted in the /goal text). Mismatch → refusal (aborted, exit 2). Absent → allowed only on a draft release; the computed lock is printed. |
| `--org UUID` | The corpus org for corpus gates. Default: the org named in the release manifest (`corpus.org_id`). |
| `--checkpoint` | Score the hidden TEST split (`ACCEPTANCE` verdict). Refused (aborted, exit 2) on a draft release or when the hidden root is absent. Reserves one hidden-budget unit per §3.6 before any hidden file is opened. Never opens `validation/`. |
| `--validation` | The founder's one-shot run on the VALIDATION split. Refused (aborted, exit 2) unless the audit-file preconditions of §3.7 hold. Never opens `test/`. |
| `--gates LIST` | Comma-separated subset of gate names to evaluate; the others print `skipped`. A diagnostic tool, never an acceptance path: ANY use of `--gates` (even naming all 17) sets `partial: true`, forces block status `ERROR` with reason `"partial run (--gates)"`, keeps `run_kind`, and exits 2. |
| `--probe-db NAME` | Reuse an existing probe database instead of creating one (tests and debugging). The name must carry the probe prefix and pass the ownership check of §12. |
| `--keep-probe` | Do not drop the probe database at the end. |
| `--report-dir PATH` | Where per-gate reports go. Default: `<release>/reports/<run_id>/` for tuning runs; hidden runs always write to `<hidden root>/releases/<name>/reports/<run_id>/` and ignore this option. |
| `--baseline-label TEXT` | Free label recorded in the block (used for the before/after-census baseline pair). |

No option may change what a gate measures. Every option value is part of `config_hash` (as `cli_options` of the closure).

### 3.2 Run sequence (observable order)

1. UTF-8 self-test (§3.9). Failure → the failure line only, exit 2 (aborted, no block).
2. Compute `runner_sha256` (§3.10). Start the input observer (§3.11).
3. Stage-1 lock verification (§4.3): manifest, criteria, schemas, fixtures, visible data files, `runner_sha256` against a frozen manifest. Mismatch → aborted, exit 2. Draft release + `--checkpoint`/`--validation` → aborted, exit 2.
4. Roster verification for the VISIBLE inputs (optimization split, fixtures, corpus roster by digest) — every record id the manifest lists exists exactly once in the visible data files and no visible record is absent from the manifest. Counts alone are insufficient. Any difference → aborted, exit 2.
5. Preflight the probe server if any fixture gate needs a database (§12); open the corpus snapshot (R6) and compute `CorpusIdentity`, `migrations_digest`, `versions`, `fixtures_digest`; build the closure; compute `code_hash` and `config_hash` (§3.11).
6. `--checkpoint`: reserve the hidden budget (§3.6) — a durable ledger event BEFORE any hidden file is opened; on a free repeat, print the recorded protected result's stdout projection and stop (exit code of the recorded status; a replay whose probe cannot be dropped prints the aborted block instead and exits 2 — §16.17(i)). `--validation`: preconditions and admission (§3.7) BEFORE any hidden file is opened.
7. Stage-2 lock verification and roster verification for exactly the selected hidden split (`test/` for checkpoint, `validation/` for validation) — never the other one.
8. Evaluate every gate (§11). Fixture gates that need a database get the probe database (§12). Corpus gates read the snapshot opened in step 5.
9. Input-observer check: every file opened and every environment variable read must lie inside the closure (§3.11); an offender → on hidden runs the run is aborted (exit 2, the reserved unit stays charged, no feedback released); on tuning runs it is listed in the block and the report.
10. Write the protected result artifact (the full block plus per-gate reports) to the report dir; record the outcome on the reservation (`--checkpoint`) or reserve the verdict (`--validation`, §3.7).
11. Drop the probe database unless `--keep-probe`; a failed drop is an infrastructure error → aborted, exit 2 (the protected result of step 10 stays on disk, marked `cleanup_failed`).
12. Print the machine block (stdout projection), then (hidden runs) one line per SET, then the verdict line exactly once as the last non-empty line; then (`--validation`) record `verdict_printed`.
13. Exit with the code of §3.5.

Interruption at any step before 12 prints no verdict (it is an aborted run: `interrupted: <class>`, exit 2, probe dropped — §16.17(e)); interruption after the verdict is printed is a completed run (a crash between 12 and its audit record is treated as printed — §3.7).

### 3.4 Criteria entry

One per criterion of the criteria file (protected result):

```
{ "id": "qs.no_content_loss", "gate": "QS", "set": "QS",
  "split": "optimization|test|validation|fixtures|corpus",
  "evidence_basis": "F|C|F+C|H-optimization|H-test|H-validation",
  "acceptance_state": "provisional|validated",
  "kind": "ratio|count",
  "numerator": int|null, "denominator": int|null, "denominator_def": string|null,
  "operator": "==|<=|>=", "threshold": number, "minimum": int|null,
  "status": "PASS|FAIL|ERROR|incomplete|pending|skipped|N/A", "reason": string,
  "expected": int, "evaluated": int, "skipped": int, "errors": int,
  "diagnostic_only": bool, "directional": bool,
  "versions": { "<component>": "<version>" } }
```

Rules:
- `kind: ratio` — a mandatory criterion with `denominator == 0` is `ERROR` regardless of `minimum` (experiments doc, common rules: a mandatory zero denominator is ERROR, never PASS); `denominator < minimum` → `ERROR`; there is no vacuous pass.
- `kind: count` — an absolute count invariant with no denominator (`denominator: null`, `minimum: null`); decided as `numerator <operator> threshold`.
- `diagnostic_only: true` entries never contribute to a gate's status; with no observations they print `status: "N/A"`.
- `directional: true` entries (declared before the freeze) never contribute PASS; on the founder run their result is reported with its interval in the protected artifact and the gate keeps its declared F/C acceptance basis; their `minimum` is informational and never turns the run into ERROR.
- `acceptance_state` is `validated` only on entries scored in a `--validation` run.
- **Stdout projection on hidden runs** (`checkpoint`, `validation`): the printed block keeps only these fields: `schema, phase, status, aborted, partial, run_kind, split_evaluated, release_name, release_state, release_lock_sha256, criteria_sha256, runner_sha256, code_hash, config_hash, corpus_digest, text_digest, migrations_digest, fixtures_digest, sets (counts only), gates (status only, no reason for hidden-evidence gates), criteria (collapsed), provisional_gates, directional_gates, hidden_budget*, validation, repeats_*, cache_*, versions, cleanup, run_id, started_at, duration_ms`. `diagnostics`, `exclusions`, `opened_outside_closure`, per-gate reasons for hidden-evidence gates, and every hidden sub-criterion are NOT printed. In `criteria`, entries whose `split` is the evaluated hidden split collapse to ONE entry per SET carrying the ACTUAL split: `{ "id": "<set>", "split": "test"|"validation", "status": "PASS"|"FAIL" }`; entries on `fixtures`/`corpus`/`optimization` splits and `pending` `.validation` entries keep the full form (they reveal no hidden case). On tuning runs the stdout projection equals the protected result.
- The criteria-entry `split` (evidence source) is a different field from a gold record's `split` (data assignment); schemas declare both.

### 3.5 Block status, gate status, exit codes

- Gate status is the conjunction of its non-diagnostic criteria: any `ERROR` → gate `ERROR`; else any `incomplete` → gate `incomplete`; else any `FAIL` → gate `FAIL`; else all `PASS` → gate `PASS`. `pending` (`<gate>.validation` outside the founder run) does not affect the gate. `skipped` only via `--gates`.
- Block status (`derive_block_status`): `integrity_ok == False` or `aborted` → `ERROR`; else `partial` → `ERROR`; else any gate `ERROR`, `incomplete` or `skipped` → `ERROR`; else any gate `FAIL` → `FAIL`; else `PASS`.
- Exit code: `PASS` → 0; `FAIL` → 1; `ERROR` → 2. A free repeat of a recorded checkpoint result exits with the recorded status's code.
- Completed runs print the verdict line; `<k>/17` counts gates with status `PASS` only.

### 3.6 Hidden budget (implemented in Stage A, exercised by tests against synthetic gold and hidden roots in temporary directories; the real hidden root does not exist yet)

- Unit: one `--checkpoint` invocation that scores ≥1 hidden TEST split under one `(code_hash, config_hash)` pair.
- **Ledger**: `<gold root>/hidden_budget.jsonl` — ONE append-only event journal for the whole gold root, outside every editable path, shared by every release, keyed per test split by `split_digest` = sha256 over the manifest entries (path + sha256 + record count, bytewise sorted) of the files under `test/<set>/`. A frozen release's manifest names the ledger it requires (`budget_ledger: "hidden_budget.jsonl"`); a required ledger that is missing or unreadable → `HiddenBudgetLedgerError`, aborted. The per-release `audit.jsonl` (§3.7) additionally records the attempt for the founder's reading; the ledger is authoritative for counts.
- **Reservation before evaluation**: `reserve` appends `{ "type": "hidden_reservation", "reservation_id", "lock", "split_digests", "code_hash", "config_hash", "run_id", "at" }` atomically (exclusive append; a concurrent reservation observes the appended count) BEFORE any hidden file is opened. An identical `(code_hash, config_hash, split_digests)` pair that already has a `completed` outcome returns the recorded protected result and appends no reservation (free repeat). A pair whose last outcome was `failed` or `cancelled` is charged again on re-execution. Failed and cancelled attempts stay charged.
- **Counters**: per split digest, the number of reservations ever recorded for that digest in the ledger (cumulative across releases — a byte-identical `test/<set>` in a superseding release inherits its spent units because the key is the digest, not the release). Effective limit per digest = 20, or the value of the latest `budget_raise` event for that digest (raise only, never lower, never reset). Exhaustion: when any selected split's counter equals its effective limit, the next new pair is refused before any hidden file is opened: aborted, exit 2, with the line `HIDDEN BUDGET EXHAUSTED <n>/<limit>` as the last line (`n` and `limit` of the exhausted split).
- **A new independent budget** exists only for a split digest composed of leakage groups never present in any previously exposed test digest; the manifest declares `test_groups_provenance` per set (the set of leakage-group ids) and a new digest that reuses an exposed group inherits the maximum counter of every digest it overlaps with.
- **Display**: `hidden n/limit (QS a · NF b · LANG c · RET d)` with `a..d` the cumulative per-split counters after this reservation, `n = max(a,b,c,d)`, `limit` the effective limit of the split that attains the max; `hidden_invocations_under_lock` (lock-local) is in the block only.
- A run that reads an environment variable outside the declared allowlist, or opens a repo file outside the closure (§3.11), is aborted before feedback is released; the reserved unit stays charged.

### 3.7 Validation guard (`--validation`) — an event-sourced journal

`<release>/audit.jsonl` holds immutable events; nothing is ever updated in place. Event types: `founder_authorization` (lock, candidate `code_hash`/`config_hash`, principal, at), `validation_admission` (attempt id, candidate, principal, session, at), `validation_verdict_reserved` (attempt id, at — written BEFORE printing), `validation_verdict_printed` (attempt id, verdict text hash, at), `validation_abort` (attempt id, reason, at), `founder_reset` (attempt id, candidate, reason, at), `holdout_consumed` (lock, cause, at), `lock_revoked` (lock, cause, at), `unauthorized_attempt` (candidate, principal, at), `budget_raise` (split digest, new limit, principal, at — also mirrored to the ledger).

`lock_state` derives: `open` (no admission), `attempted` (an admission with an abort that a reset covers), `consumed` (a printed verdict by the authorized principal, or a second abort, or an explicit `holdout_consumed`), `revoked` (a `lock_revoked` event, or a verdict printed under an admission whose principal is not the authorizing founder's).

Preconditions, checked BEFORE any hidden file is opened: (a) a `founder_authorization` for this lock naming exactly the candidate's `(code_hash, config_hash)`; (b) `lock_state` is `open`, or `attempted` with exactly one abort — a `validation_abort`, or an admission that carries no terminal event (`validation_abort`, `validation_verdict_reserved`, `validation_verdict_printed`), which counts as an abort — covered by a `founder_reset` naming its `attempt_id` for the SAME candidate (§16.17(j)); (c) `validation_admission` appended (with principal and session) before execution. A missing authorization → `unauthorized_attempt` appended, aborted, exit 2, holdouts not consumed (nothing was read). The aborted attempt's `reports/` directory is sealed (renamed `<run_id>.sealed`) and not read before the re-run. A verdict-reservation without a matching `validation_verdict_printed` is treated as printed (consumed) — a crash after printing never qualifies as an unprinted-verdict reset. After a printed verdict, every further `--validation` on the same lock is aborted, exit 2, forever. The validation run charges no hidden unit, scores H-split gates on the validation split, prints `validation=complete` in place of the `hidden` field, and sets `acceptance_state: validated` on the entries it scores.

### 3.8 Verdict line — the exact grammar (one grammar for every run)

```
STEP1 <TUNING|ACCEPTANCE>: <k>/17 PASS | provisional=<p>:<gates or -> | hidden <n>/<limit> (QS a · NF b · LANG c · RET d) | directional=<gates or -> | run_id=<id> | lock=sha256:<64 hex> | runner=sha256:<64 hex>
```

- `TUNING` for every run whose H-split gates were evaluated on the optimization split (or not at all); the `hidden …` field is ABSENT.
- `ACCEPTANCE` for `--checkpoint` (H-split gates carry `"split":"test"`); the `hidden` field present; `<limit>` is `20` unless raised.
- The founder's `--validation` run prints `ACCEPTANCE`, no `hidden` field, and `| validation=complete` immediately before `directional=`.
- `provisional=<p>:<list>` — `p` is the count and the list is the derived `provisional_gates` in the frozen order `FID,THR,IDENT,ATTR`, comma-separated without spaces, never annotated; `provisional=0:-` is only reachable by the founder run.
- `directional=-` when no gate was declared directional before the freeze; otherwise the directional gates in frozen order.
- Separator is ` | ` (space, pipe, space); the per-split bracket uses ` · ` (space, U+00B7, space).
- `<id>` is the `run_id`; `<64 hex>` is lowercase.
- Printed exactly once, as the last non-empty line, on stdout, after the machine block and after any per-SET hidden lines, after cleanup. Never printed on an aborted run.
- On hidden-split runs, above the verdict line: exactly one line per SET evaluated on the hidden split, `<SET>: GATES PASS` or `<SET>: GATES FAIL`, nothing finer.

### 3.9 UTF-8 self-test

Before any other output the runner forces UTF-8 on stdout/stderr and proves it: it writes the line `MEM01 UTF-8 self-test: Здравей, свят — кирилица OK` to stdout, encodes the same string to bytes and back, writes it to a temporary file and reads it back, and compares all three. Any mismatch or exception → exit 2 with the line `MEM01 UTF-8 self-test FAILED`. Every file the instrument writes is UTF-8; every subprocess it spawns is decoded as UTF-8 explicitly.

### 3.10 `runner_sha256`

Merkle digest over `backend/tools/mem01_verify/`: for every regular file (recursively, excluding ONLY bytecode per `hashing.is_bytecode` — e.g. `x.cpython-312.pyc` and CPython's temp name `x.cpython-312.pyc.140213`; no directory is excluded — §16.16(r), v1.2.8), the line `"<posix relative path>\t<sha256 of bytes>\n"`, lines sorted bytewise, then sha256 of the concatenation. Printed in the verdict line on every completed run. On a frozen release it must equal `manifest.runner_sha256` or the run aborts (exit 2). On a draft release it is recorded, not enforced.

### 3.11 Closure, `code_hash`, `config_hash`, and the input observer

- The **closure** is built BEFORE evaluation (step 5) and is the candidate's identity. `code_hash` = `canonical_lines_digest` over `"<path>\t<sha256>\n"` for every file under `backend/app/` and `backend/tests/mem01/` (the editable scope) plus `backend/pyproject.toml`, `backend/uv.lock` and `backend/.python-version` (dependencies and native tools, per the /goal text). `config_hash` = sha256 over the canonical JSON of: `criteria_sha256`; the bytes-hash of every declared config artifact with `hashed: true`; the declared env allowlist NAMES (the list itself, per the /goal text — values are not hashed; secret-bearing artifacts such as `backend/.env` are declared with `hashed: false`); `migrations_digest`; `corpus_digest`; `fixtures_digest`; `versions`; `cli_options`.
- The **input observer** records every file path this process opens and every environment variable it reads from step 2 to step 9, and the process launches it makes (child processes are declared in the closure by command line and are themselves run with an explicit, minimal environment). At step 9 every observed repo file must lie inside editable scope ∪ declared config artifacts ∪ the runner folder ∪ the release directory, and every observed environment variable inside the allowlist; offenders are listed in `opened_outside_closure`. On hidden runs an offender aborts the run before any feedback is released (the reserved unit stays charged); on tuning runs it is a warning in the block and the report.
- The observer is telemetry over the interpreter's own file and environment access; it does not claim to see native or child-process reads — those are covered by declaring child commands and their inputs in the closure, and the census/snapshot inputs are identified by `corpus_digest` and `migrations_digest`.
- Undeclared mutable state is an error: the corpus digest and the migrations digest are the declared identity of the database state.

### 4.2 Manifest

`dataset.manifest.json` lists: `release_name`, `release_state` (`draft`|`frozen`), `cut_at`, `runner_sha256` (the value at cut time), `criteria_sha256`, `protocol_sha256`, `schemas` (path → sha256), `files` (every data file path → `{ sha256, bytes, records, visibility: "visible"|"hidden" }` — hidden paths are namespaced `hidden/test/<set>/…` and `hidden/validation/<set>/…` and resolve under the hidden root), `records` (per SET → per split (`optimization`/`test`/`validation`) sorted lists of `gold_id`, or `{ "by_digest": "<corpus_digest>", "roster_counts": {…} }` for corpus rosters — §16.13), `corpus` (`org_id`, `emails`, `attachments`, `corpus_digest`, `text_digest`, `snapshot_manifest_sha256`), `fixtures_digest`, `cells_out_of_scope` (empty in Stage A), `sets` (per SET: expected record count, evidence kinds), `budget_ledger` (required on frozen releases), `test_groups_provenance` (per set, frozen releases). Hashes and counts reveal no case content. `reports/` and `audit.jsonl` are never in the manifest.

### 4.3 The lock — staged verification

`release_lock_sha256` = sha256 of the manifest file bytes.

- **Stage 1 (visible)** — always, before any data or database access: recompute and compare the manifest's own hash against `--expect-lock` when given; recompute the sha256 of every VISIBLE file the manifest names (criteria, protocol, schemas, fixtures, `data/optimization`, snapshot manifest, census, leakage, bootstrap) and compare; on a frozen release compare `runner_sha256`. Hidden paths are NOT opened. Any mismatch → aborted.
- **Stage 2 (hidden)** — only after the reservation (`--checkpoint`) or admission (`--validation`) is durably recorded: recompute and compare exactly the files of the selected split (`hidden/test/*` for checkpoint, `hidden/validation/*` for validation). The other split is never opened. Any mismatch → aborted (the reservation stays charged; a validation admission is recorded as aborted).
- A `frozen` release refuses to run if any visible file under it other than `reports/**` and `audit.jsonl` is not in the manifest or differs from it; a `draft` release verifies the files it names and tolerates extra files (the census, leakage and bootstrap outputs are added to a draft after its cut and re-manifested by `release cut --draft` again).

### 4.4 Cutting

`python -m tools.mem01_verify.release cut --draft` produces or refreshes the draft layout (idempotent: re-running over an unchanged gold root produces a byte-identical manifest except `cut_at`); the census, leakage and language-bootstrap instruments run separately through `release instruments --draft` and are re-manifested by the next `cut` (§16.12). `--freeze` is reserved for stage B and must refuse in Stage A. **Freeze preconditions (recorded here so stage B cannot forget them):** `data/optimization` non-empty; the hidden root present with `test/` and `validation/` populated at leakage-group level; `test_groups_provenance` declared; the budget ledger present; and an audited separation of hidden inputs from every visible artifact — the full-corpus snapshot under the visible release is draft-only and must not remain visible for records assigned to hidden splits (blindness begins at freeze: gold-standard §5.6, §10a; the experiments doc's "one split for all layers, enforced on all surfaces"). See founder note N8.

### 4.5 The criteria file — the normative annex

`backend/tools/mem01_verify/release/criteria.step1.v1.yaml` IS the exam's formula sheet: the complete criterion catalogue with every slice's id, formula, threshold, minimum, edge policies and evidence source, transcribed from the frozen criteria sheets. It is part of this contract (the oracle author reads it). Undecided stage-B values (tokenizer pin, legacy-format identities, designated boilerplate, the ATTR ceiling, draft minimums marked `founder_draft: true`) are explicitly unresolved and cannot produce PASS on their own.

Every gate has ≥1 non-diagnostic criterion; FID/THR/IDENT/ATTR each have `<gate>.provisional…` entries and `<gate>.validation…` entries (`split_source: validation`). `load_criteria` rejects a file missing any field, an unknown gate, a duplicate id, a `zero_denominator` other than `error`, a `ratio` with `minimum` < 1, a `count` with a non-null denominator, a partner id that does not exist, or a `provisional_gates` list not equal to the frozen four in order.

### 4.6 Scope policy (COV; ruling (a)) — by independently established properties

Exclusions come ONLY from the frozen scope policy and independently established properties of the input; the measured component cannot create its own exclusion, and an extraction status cannot establish delivery on its own.

- **Explicitly excluded** — an attachment whose MIME class (from the message part's declared `content_type`, a header property, not the extractor's decision) is in the frozen non-document list (`image/*`, `audio/*`, `video/*`, and the exact types the policy lists: signatures, calendar parts, fonts), or that is an inline image (`is_inline` with an image MIME). The policy names the list; the reason is recorded per input.
- **Delivered** — a required input whose stored text handoff is complete: `extraction_status == extracted`, non-null non-empty `extracted_text`, `extractor_name` and `extractor_version` recorded, no `truncated`/partial marker; for emails: `parse_status == parsed` with a non-null body.
- **Not ready** — every required input that is neither excluded nor delivered, INCLUDING any input the extractor marked `skipped_nondocument` whose MIME class is NOT in the frozen exclusion list (the component may not manufacture an exemption), and any `unsupported_format`, `scanned_pending_ocr`, `extracted_partial_scanned`, `truncated`, `corrupt`, `encrypted`, `empty`, `pending`, `skipped_oversize`.
- `legacy_by_file_identity` (stage B): content hashes of `.doc`/`.xls` with disposition `converted` | `excluded`.

## 5. Snapshot emitter — `SNAPSHOT_V1` — and corpus identity — `CORPUS_DIGEST_V1`

### 5.1 Text snapshot

- **Artifacts** (per ruling (g): the legacy input snapshot is the exact UTF-8 text stored after sanitize and secret-redaction):
  - `email_body:<email_message.id>` → `email_message.body_text`
  - `email_subject:<email_message.id>` → `email_message.subject` (a retrieval surface; stored without sanitization — recorded as-is)
  - `attachment_text:<email_attachment.id>` → `email_attachment.extracted_text`, only when non-null
- **Record** (one JSON line per artifact): `artifact_id, kind, source_table, source_id, org_id, sha256` (of the UTF-8 encoding of the stored string; a NULL value is recorded as the empty string with `stored_null: true`), `byte_len`, `scalar_len` (Unicode scalar count), `line_count` (= number of `\n` characters, plus one if the text is non-empty and does not end with `\n`; 0 for empty), `stored_null`, `beyond_redact_scan_cap` (`scalar_len > 2_000_000`), `stored_versions` (`extractor_name`, `extractor_version`, `extraction_status` for attachments; `parse_status` for emails), `text` (verbatim).
- **Manifest**: `snapshot.manifest.jsonl` with the record minus `text`, sorted by `artifact_id` (bytewise); `text_digest` = `canonical_lines_digest` over `"<artifact_id>\t<sha256>\t<stored_null>\n"`.
- **Determinism**: two clean replays over an unchanged corpus produce byte-identical manifests and the same `text_digest` (SNAP criterion 16, C part). `compare_manifests` reports counts only (added, removed, changed, unchanged).
- **Plane**: the emitter reads the whole org through the R6 snapshot session (never the person-bound reader plane, which without a person serves only org-visible rows — zero rows on today's all-restricted corpus).
- **Offsets**: every later label addresses these artifacts by UTF-8 byte offsets (gold-standard §2.1); span arithmetic later runs in Unicode scalar positions (gold-standard §7.2, v5.3 — see founder note N9). The snapshot records both lengths so either can be validated.
- **Storage**: under `<release>/snapshots/<text_digest>/` — contains personal data, outside the repo, draft-only (§4.4).

### 5.2 Corpus digest — the candidate's database identity

`corpus_digest` identifies the complete measured database state, not just the text. It is `canonical_lines_digest` over canonical JSON lines (sorted keys, `ensure_ascii=False`, one line per row, prefixed by the table name, ordered by table then primary key) of every gate-relevant column, taken inside the R6 snapshot:

- `email_message`: `id, connection_id, dedup_key, message_id, in_reply_to, references, from_address_sha256, from_person_id, subject_sha256, sent_at, received_at, body_sha256, body_stored_null, direction, is_automated, is_reply, has_attachments, word_count, language, headers` (the retained header map, values as stored), `size_bytes, parse_status, visibility_scope, origin_scope, container_id`.
- `email_attachment`: `id, email_id, filename_sha256, content_type, size_bytes, content_hash, is_inline, content_id, extracted_text_sha256, extracted_text_stored_null, extraction_status, extractor_name, extractor_version, extraction_detail, extracted_data_sha256, visibility_scope, origin_scope, container_id`.
- `email_recipient`: `id, email_id, kind, address_sha256, person_id`.
- `person`: `id, is_internal, display_name_sha256`; `person_email`: `id, person_id, email_sha256, source`; `person_alias`: `id, person_id, alias_sha256, source` (v1.2.8: `source` added — the implementation digests it and a wider digest is strictly more sensitive).
- `acl_grant`: `id, person_id, object_type, object_id, connection_id, provenance, granted_at, revoked_at`; `principal_source_identity`, `visibility_promotion`, `fact_provenance`: all columns except free text (hashed).
- `alembic_version.version_num`; the org's `connector_connection` rows (ids, mailbox hash).

Personal-data columns enter only as sha256 of their UTF-8 bytes (`*_sha256`); timestamps as ISO-8601 UTC. Any change to any listed value, nullness, or row set changes `corpus_digest`. `text_digest` (§5.1) is reported beside it and is a strict function of the text artifacts only. The roster's `{ "by_digest": corpus_digest, "roster_counts": {…} }` shortcut therefore establishes complete row-id equality for every table listed.

## 6. EVID_NORM_V1

Purpose: find a quote inside a snapshot artifact tolerant of typographic variation, then map the match back to ORIGINAL offsets. Normalization finds the match, never measures it.

- **Normalization** (pure, deterministic, versioned `EVID_NORM_V1`; NO Unicode normalization form is applied — combining sequences are left as stored, so the offset map stays monotone): typographic double quotes (`„ “ ” « » ‟ ″`) → `"`; single quotes and apostrophes (`‘ ’ ‚ ‹ › ′ ʼ`) → `'`; dashes (`‐ ‑ ‒ – — ― −`) → `-`; ellipsis (`…`) → `...`; zero-width space / joiner / non-joiner / BOM / soft hyphen → removed; NBSP, narrow NBSP, thin, hair, en, em, figure, punctuation spaces and ideographic space → a space; any run of whitespace (including newlines and tabs) → one space; leading/trailing whitespace stripped. Case is preserved. Letters are never transliterated (Cyrillic stays Cyrillic). The mapping table is a frozen constant of the module and is part of the version.
- **Units**: every surviving source scalar produces exactly one normalization unit in the output: a single character, a multi-character expansion (`…` → `...`, one unit of length 3), or — for a whitespace run — one unit (a single space) whose source is the whole run. `Normalized.unit_starts` marks the normalized position where each unit begins; `source_positions[i]` is the source scalar position of the unit containing normalized position `i` (for a whitespace-run unit, the position of the run's first scalar). Deleted scalars produce no unit.
- **Offset map**: `to_original(start, end)` requires `start` and `end` to be unit boundaries (`start ∈ unit_starts`, `end ∈ unit_starts ∪ {len(text)}`) and returns the MINIMAL original span `[a, b)` covering the source scalars of those units — for a whitespace-run unit the whole run; leading/trailing scalars that were deleted (zero-width) or trimmed are never included. Positions inside a multi-character expansion are not valid boundaries (`NormalizationError`). The mapping is not a bijection and never claims one.
- **Resolution**: `resolve(quote, artifact_text)` normalizes both; a match is an occurrence of the normalized quote in the normalized artifact whose start and end are BOTH unit boundaries (an occurrence that starts or ends inside a multi-character expansion is not a match — `"."` does not match inside `…`); matches are deduplicated by original interval; the result is exactly one of: `resolved` with one span; `ambiguous` with all distinct candidate spans (≥2); `unresolved` when there is no unit-aligned occurrence, when the quote is empty, or when the quote normalizes to the empty string. Every span carries scalar and UTF-8 byte offsets into the ORIGINAL artifact.
- **Round-trip property** (the required test): for any generated text (Bulgarian, English, mixed, with curly quotes, dashes, NBSP, CRLF, emoji, combining marks, repeated fragments) and any substring `s` of the ORIGINAL whose normalization is non-empty: (i) `resolve(s, text)` is `resolved` or `ambiguous`; (ii) the original substring `s`, after removing leading and trailing scalars that normalize to nothing or to whitespace, equals the original text of one returned span after the same trimming; (iii) `normalize(text[span]).text == normalize(s).text` for EVERY returned span; (iv) `source_positions` is non-decreasing and `to_original` of the full normalized text is `[first_kept, last_kept + 1)`. The test must generate cases, not only enumerate them; if a property-testing dependency is added it is declared in `pyproject.toml`.
- **NUM_NORM_V1** is Phase 1 and NOT part of Stage A.

## 7. Leakage-group instrument — `LEAK_GROUPS_V1`

Separate from production threading (which does not exist). Conservative over-merge is acceptable for splitting; real groups are never cut by a threshold; boilerplate is excluded only by a frozen designation.

- **Nodes**: emails of the org.
- **Edges** (an email pair is joined when any holds): (1) `reply`: `in_reply_to` of one equals `message_id` of the other; (2) `reference`: any `references` token of one equals `message_id` of the other; (3) `collision`: both carry the same `message_id` (a reused id — grouped, counted separately); (4) `sibling`: both carry the same non-null `in_reply_to`, or share any `references` token, whether or not the referenced id exists in the corpus (siblings under an external parent); (5) `attachment`: both carry attachments with the same `content_hash`, unless that hash is in the frozen `designated_boilerplate` set (stage B, from the review list) or the attachment is an inline image (`is_inline` with `image/*`) — the only property-based exclusion; (6) `template`: both have the same non-null `normalized_body_sha256` (exact duplicates after EVID_NORM_V1 — the frozen v1 template rule; near-duplicate similarity clustering is deferred to stage B and stated as such in the summary).
- **Review trigger, not a classification**: hashes carried by more than `UBIQUITY_REVIEW_TRIGGER = 25` distinct emails are listed in `review_trigger_hashes` with their carrier counts for the founder's boilerplate designation; until designated they JOIN (over-merge is acceptable; a whole-corpus collapse is visible in `largest_sizes` and is a finding, not something the instrument silently prevents).
- **Output**: `leakage_groups.jsonl` — one line per group: `group_id` (sha256 of the sorted member email ids joined by `\n`), `email_ids` (sorted), `size`, `edge_counts` by kind, `attachment_hashes` that joined; plus `leakage.summary.json`: version, constants, group count, size histogram, the ten largest group sizes, singleton count, `review_trigger_hashes`, `designated_boilerplate_applied`, `collision_edges`, `sibling_edges`, `template_edges`, the input `corpus_digest`, and the statement that near-duplicate clustering beyond exact normalized-body identity is not implemented in V1.
- **Invariant**: every email belongs to exactly one group; the union of groups equals the roster; `group_rows` over the same input in any order yields identical output.
- Reads the R6 snapshot; no index is added.

## 9. Census — `CENSUS_V1`

A versioned instrument, not a one-off script: its SQL is inside the emitted file, its version and the corpus digest identify the observation.

Metrics (each emitted as `{ "value", "sql", "denominator_for", "unit" }`), over the corpus org, inside the R6 snapshot:

- Emails: total; body non-empty; body empty; parse failed; `message_id` null; distinct `message_id`; reused `message_id` groups and members; `in_reply_to` present; `references` present; `Content-Language` present and its value distribution; `language` null; `sent_at`/`received_at` null; `sent_at == received_at`; `is_reply`; `has_attachments`; `is_automated`; direction; visibility/origin scope distribution; body byte length min/p50/p90/p99/max; bodies beyond the redact scan cap; dedup-key duplicate groups; header key coverage (every retained header → count).

## 10. Fixtures — `FIXTURES_V1` (public F evidence, PII-free, synthetic)

All fixtures live under `backend/tools/mem01_verify/fixtures/` as Python data modules or generated bytes (no files with personal data; no real corpus text; addresses only under the reserved domains `example.test`, `acme.test`, `partner.test`). Every fixture record is a frozen dataclass carrying `case_id`, `criterion_id`, `origin`, `expected`. **Fixture EXPECTATIONS are authored by an agent that is not the evaluator's implementer** (builder ≠ labeler) and are NEVER computed by running a measured component (R12). The fixture battery digest is part of `config_hash`.

10.1 **Org × persona matrix (VIS)** — ≥2 orgs (A, B), ≥3 personas in A (A1 owner/`to` recipient with grants, A2 `cc` recipient with grants on a subset, A3 blind-copied only, no grant), ≥1 in B; states per message: restricted-with-grant, restricted-without-grant, org-visible (with promotion lineage), grant revoked, no person bound; shared attachment (same `content_hash` in A and B); pooled-session reuse (two personas sequentially on one connection). Every route × state cell has ≥1 positive and ≥1 negative probe; a persona that sees nothing anywhere makes the fixture invalid (deny-all = FAIL). Also: BCC membership never appears in any row a non-BCC persona can read; a reader without a person bound sees exactly the org-visible rows and zero restricted rows (the matrix contains both kinds, so this cell has a positive and a negative probe too).
10.2 **TIME** — ≥30 `Date` header cases: explicit positive/negative offsets, `-0000` (RFC 5322: unknown zone), missing zone, malformed, DST-transition instants in both seasons, two-digit years, obsolete comments, whitespace variants; each with the expected instant (ISO-8601 UTC) or the expected `unknown_zone` / `malformed` state, specified from the RFC, never from `parse_date`. Plus the C comparison: ≥100 corpus rows' stored `sent_at` compared with the retained `Date` header (aggregates only in reports); `sent_at == received_at` is a diagnostic, not defect evidence on its own (`received_at` legitimately falls back to `Date` when no INTERNALDATE exists).
10.3 **RED** — the surface matrix `red_surfaces` names every real production handoff a secret can travel: `email_body` (the parser's body path), `attachment_text` (the extractor's text path), `attachment_structured_payload` (`extracted_data`), `extraction_detail`, `embedding_header` (`incomplete` until stage D), `logging` (the ingest log output for a message carrying a canary — exercised through the parser's degraded-parse handoff and guarded against vacuity, §16.17(a)–(b)). ≥10 positive canaries per class (AWS, OpenAI, Google, GitHub, Slack, Stripe, JWT, PEM block, keyed value with entropy, connection-string password), each passed through every available surface, including canaries placed beyond scalar position 2,000,000 and canaries straddling that boundary; ≥100 hard negative controls that must survive untouched (invoice numbers, IBAN-shaped synthetic strings, EIK-shaped numbers, phone-shaped numbers, dates, URLs, ordinary hashes, Bulgarian prose with digits). A surface with no implementation is recorded `incomplete`, never PASS.
10.4 **IDENT** — ≥20 confirmed alias pairs (with provenance) that must resolve to one identity; ≥40 must-remain-distinct pairs (dot/plus variants, same display name on different domains, role addresses, look-alike domains, IDN); exact-address stability controls. Plus the C invariants over the corpus: participations without a versioned normalization key or without a retained raw address = 0 (ratio); identity merges without a confirmed alias with provenance = 0 (count invariant).
10.5 **FID** — for EVERY supported format that can carry tables, links or multi-column layout (pdf, docx, xlsx, html, rtf, and tnef-embedded documents) ≥3 fixtures carry the full unit taxonomy (paragraphs/list items in order, link label→destination pairs, page/column order, table tuples `(sheet,row,column,value,header)`); per supported format (pdf, docx, xlsx, tnef, html, rtf, plain text) ≥10 fixtures; ≥30 encoding/Unicode cases. Expectations come from the synthetic ORIGINAL; scoring reads the declared DOWNSTREAM payload after every transformation — in Stage A the stored `extracted_text` value exactly as the ingest path stores it (post-sanitize, post-mask), never an intermediate object; column swaps, lost negations and values under a wrong header FAIL; a unit the handoff cannot represent FAILS (that is what the gate is for).
10.6 **IDEM** — ≥10 replay scenarios with synthetic `.eml` bytes on the probe database: first ingest creates (positive control), replay with identical versions adds zero logical rows, retry after a simulated failure adds zero, concurrent duplicate ingest adds one; explicit version backfill is `incomplete` until stage C.
10.7 **SNAP** — ≥30 normalization/mapping cases (Cyrillic, emoji, combining marks, CRLF, NBSP, repeated text, typographic punctuation, zero-width characters, whitespace-run spans, quotes inside expansions) with expected resolved/ambiguous/unresolved outcomes and original spans; plus the two-replay hash equality over the corpus.
10.8 **COV** — ≥20 scenarios for the scope policy of §4.6: duplicates, exclusions by MIME class, a `skipped_nondocument` on a non-excluded MIME class (must be not-ready), parser failures, partial extraction, empty documents, a delivered document missing its extractor version (not-ready).
10.9 **THR / ATTR / CH / NF / LANG / RET / EMB / ERASE / QS** — fixture SHAPES and schemas are defined (so the release schemas are complete) but their batteries are stage B/C work; Stage A ships the schema and zero or a handful of smoke cases, and the gate prints `incomplete`.

## 12. Probe database lifecycle

- Name `mem01_probe_<run_id>` (or the `--probe-db` name), created on the configured server, migrated with the project's Alembic to head; runtime roles already exist cluster-wide (migrations create them `IF NOT EXISTS`, NOLOGIN); the instrument NEVER provisions, alters or re-passwords a role.
- **Preflight** (`preflight_probe_server`), before creating anything: the three runtime roles exist and can LOG IN with the configured credentials; the owner can create databases; the list of stale probes is taken. A failed preflight → `ProbeDatabaseError`, aborted — never a provisioning attempt.
- **Targeting is a safety boundary.** The application's settings are cached process-wide and Alembic's environment takes its URL from them, so the instrument never runs Alembic in-process: the migration runs in a child process whose environment names the probe database, and before creating, migrating or dropping anything the instrument asserts that the target name starts with `mem01_probe_` and differs from the configured database name (`ProbeDatabaseError` otherwise). `DROP DATABASE` is only ever issued for a name carrying that prefix. Every probe connection the instrument opens is verified (`current_database()`) to be the probe before any fixture is written.
- **Exclusive ownership and empty start**: a freshly created probe is verified empty of tenant rows after migration; a `--probe-db` name is accepted only if it carries the prefix, is not registered as owned by another running run (a `probe_owner` marker row written by the creating run and checked by the reuser), and is otherwise reset by the caller — the instrument never truncates a probe it did not create.
- Fixture gates load their fixtures through the REAL write plane (the ingest service where a scenario is an ingest; tenant-scoped sessions otherwise) and read through the REAL reader plane (`reader_session(org_id, person_id)`); no privileged setup connection ever plays the reader.
- Dropped before the verdict is printed unless `--keep-probe` (§3.2 step 11); a leftover probe database from a crashed run is reported by the next run (`stale_probe_databases` in diagnostics) and never reused silently.
- The tests under `backend/tests/tools/mem01_verify/` create their own probe database per session and drop it; they never open the configured database's tables, and their conftest must not import or trigger any corpus-truncating fixture.

16.12 **Determinations from the in-house seal review (v1.2.4).**
- **Verdict parser bounds:** `<k>` must satisfy `0 ≤ k ≤ 17` (`18/17` is rejected); `provisional=<p>:<list>` is accepted with any `p` in `0..4` on EVERY run kind (after a founder run a later tuning run legitimately prints `provisional=0:-`), so `provisional=0:-` on a `TUNING` line is well-formed; the parser checks only order, separators, the frozen gate order, and consistency of `p` with the list length.
- **`append_event` is an envelope writer, not a schema validator:** it requires a `type` key (non-empty string), generates `event_id` (uuid4) and `at` (ISO-8601 UTC, seconds, `Z`) when absent, refuses an event that already carries `event_id`, and appends exactly one JSON line atomically. The type-specific key sets of §16.1 are enforced by the modules that WRITE those events (`hidden_budget`, `validation_guard`, `release`), whose emitted events must equal `type, event_id, at` plus exactly the listed keys.
- **Probe run ids:** `create_probe_database(run_id)` validates `run_id` against the §16.3 grammar and raises `ProbeDatabaseError` otherwise; tests mint conforming ids.
- **Cut versus instruments (§4.3/§4.4/§13 reconciled):** `release cut --draft` produces the layout, the corpus identity, the text snapshot (deterministic), copies criteria/protocol/schemas/fixtures, creates empty `census/`, `leakage/`, `lang_bootstrap/` directories, the empty release `audit.jsonl` and the gold-root ledger, and writes the manifest; it NEVER runs the census, leakage or language-bootstrap instruments. Re-running `cut` over an unchanged release is byte-identical except `cut_at`.
