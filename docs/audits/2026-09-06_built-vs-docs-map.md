## 1. Executive summary

1. **Connect is LIVE but through the wrong door.** 5,893 emails / 8,454 attachments / 839 people are ingested, deduplicated, text-extracted and grant-stamped on the live DB — all of it loaded by a dev disk script (`backend/scripts/ingest_imap_dump.py`), never by the production sync runner (`connector_sync_run` = 0 rows).
2. **Ask is LIVE only inside its own eval harness.** The 6-tool retrieval layer runs against the real person-bound reader plane (last real run 2026-07-09, 4 questions, 0 errors), but no route reaches it — `backend/app/main.py:80-83` registers health/identity/connectors/access and nothing else.
3. **Learn is ABSENT as a product and STUB as schema.** `fact_provenance` and `visibility_promotion` exist and hold 0 rows; pgvector 0.8.2 is installed and **zero columns anywhere are vector-typed**; MEM-01 is four design documents, no code.
4. **Platform is a split verdict:** the database half is LIVE and genuinely enforcing (22 tables with FORCE RLS, 4 privilege-separated roles, an append-only audit trigger); the application half — JWT auth, platform console, GDPR erasure, break-glass — is CODE_COMPLETE and has **never run once against real data**.
5. **The audit trail, which the MCP-01 pitch sells, is empty for real data.** All 162 `audit_log` rows belong to 99 throwaway pytest orgs; `SELECT count(*) FROM audit_log WHERE org_id='d1500000-0000-0000-0000-000000000001'` → **0**.
6. **Biggest risk (single):** ~15,000 lines — the entire ASK-01 tool layer, its 19 test modules, the security-seal harness, migrations 0022/0023 and the MEM-01/EXP-002 decision record — exist in **exactly one copy**: an uncommitted working tree on a branch with no remote. Nothing is staged (`git diff --cached --numstat` → 0 lines). Worse, the live DB is stamped at `0022_counterparty_summary_v3`, a revision that exists in **no git object** — a `git stash` or branch switch destroys the code *and* orphans the database.
7. **Most misleading document (single):** `docs/PM/ask/ASK-SECURITY-LEDGER.md` — it records V9/V11/V12 as CLOSED "by migration 0023", which is untracked and unapplied; on the live DB those three disclosures are **open and measured** (59 BCC rows readable, 10 counterparty domains disclosed via BCC alone, all 5,893 `acl_grant` rows enumerable). Runner-up: `CLAUDE.md:3`, auto-loaded into every session, still says "no product features yet".
8. **Freshness:** the newest row anywhere in the database is 2026-07-09; the last commit is 2026-07-06 (62 days ago); the app containers have been down ~2 months. The mid-August Cowork demo milestone (`CLAUDE.md:10`) passed 3 weeks ago with no MCP server in the tree.
